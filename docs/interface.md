# The interface: ribbon, commands and palette

*Versão em português: [interface.pt-BR.md](interface.pt-BR.md).*

ConstructCraft's window follows the layout desktop CAD and BIM users expect. The **quick access toolbar** sits at the top left. Below it is the **ribbon**, a row of tabs with groups of buttons. The **options bar** for the active tool comes next. The **project browser** and **properties** are docked on the left, the **views** fill the tabs in the middle, and the **status bar** is at the bottom. The project browser and properties start stacked on the left; drag a panel's header to dock it on either side: onto the strip along the window's left or right edge for a column of its own there, onto the top or bottom half of the other panel to stack it above or below, or onto its left or right half for a column of its own beside it. The area the panel will take is highlighted while dragging, and Esc cancels. Right-clicking a header offers the same choices (*Dock on the left*, *Dock on the right*, *Stack with…*, *Separate from…*) and *Reset panel layout*, also in *Preferences → Interface*. The layout is kept between sessions. When many views are open, **Close Inactive Views** (in the quick access toolbar and in *View → Windows*) closes every tab but the active one, and right-clicking a tab offers *Close Other Views*. The arrow at the right end of each tab bar (**Open Views**) lists the views open in that bar, grouped by view type as in the project browser, with the active one checked: picking one brings its tab to the front and scrolls it into view. Below the list, *Close Other Views* closes the bar's other tabs and *Close All Views* all of them. The mouse wheel over a crowded tab bar scrolls its tabs. Closing the last open view closes the project and returns to the home screen, asking first when there are unsaved changes.

Opening a project and importing a file (IFC, DWG/DXF, SketchUp, OBJ, glTF, pictures and SVG, component files) read it in the background: a dialog shows the operation, the file's name, folder and size and the time elapsed, with a spinner, and keeps the rest of the window from being used. The open project stays as it was until the file has been read; *Cancel* (or Esc) stops waiting and changes nothing.

A new project (*New* in the quick access toolbar and on the home screen, Ctrl+N) starts from a template: the *New Project* dialog offers the **Metric System** (meters, 1:50 and 1:100 scales, A sheets) and the **Imperial System** (feet and inches, 1/4" = 1'-0" scales, ANSI and ARCH sheets, ANSI B to start) as two cards. Click one and *Create*, or double-click it; the template picked last is picked first next time. With unsaved changes, the question about them comes after *Create*, and *Cancel* in either leaves the open project as it is. In an imperial project the scale pickers (view properties, view templates, the Callout tool) offer the architectural and engineering scales (`1/4" = 1'-0"`, `1" = 20'-0"`…) and views, sheets and the view's toolbar write scales that way; a scale outside the list still shows as `1:N`. Sizes on paper (dimension and level mark text sizes, dimension style marks and gaps, pen weights, text note widths, viewport positions, custom paper, drafting fill patterns) read and are typed in inches in an imperial project (`3/32"`, pen weights as `0.010"`); a bare number is inches, and `mm` or `cm` after it still give millimeters. Title block and detail component piece fields stay expressions in millimeters.

*Open* (in the quick access toolbar and on the home screen, Ctrl+O) takes a project or an IFC file, imported as a new project as *Import IFC…* (on the home screen and in *Insert*) does. In a build with the `rvt` feature (off by default: `cargo run -p cc_app --features rvt`) it also takes a Revit project (`.rvt`), converted to IFC without Revit in a separate process and imported the same way, as *Import Revit…* does (the status bar says how many elements came in only as their bounding box, their shape not read, and how many notes the converter left). The result has no file until it is saved. A file Open takes, dropped on the window, opens too, also on the home screen; DWG, DXF and SVG drawings and pictures dropped on an open project go into the active view. On macOS, a file double-clicked in Finder or opened with *Open With* does not reach the app yet: open it from ConstructCraft.

**Measurement systems.** Everything measured follows the project's units (*Manage → Project Units*), so switching them between metric and imperial (the *Imperial (US)* button there) changes every display at once. In an imperial project lengths read in feet and inches (`12'-6 1/2"`), while small sizes — layer and slab thicknesses, section sides, diameters, risers and treads, tray sections, profile dimensions — read in inches without feet (`3/4"`, `1 1/4"`, `16"`) and a bare number typed in those fields is inches; areas and volumes read in square and cubic feet, slopes as the rise per 12 of run (`6:12`, typed as `6:12`, `6/12` or `6`; *Rise per 12* is also offered to metric projects), masses in pounds (`lb`, `lb/ft` for profiles, `lb/ft²` for roof coverings), densities in `lb/ft³`, strengths in `ksi`, pipe flows in `gpm`, section properties in `in²`, `in⁴`, `in³` and `in`, the site map's scale in feet and miles. Schedule headers name no unit there (`Length`, not `Length (m)`), since the values carry their own marks. Things made on demand get round imperial sizes and names without metric units: the baseboard (4"), ramp (4'-0", with 1:12 slope, 30" rise and 60" landing rules), cable tray (8" × 4"), lightning conductor (Ø3/8"), curtain wall (5'-0" grid, 2" × 6" mullions) and door types (2'-8" × 6'-8"), and the devices; new walls are 10'-0" tall, pipes and devices sit at round heights, drains fall 1/4" per foot up to 3" and 1/8" above, and free points snap to 1/2" to 20'-0" steps by zoom. The imperial template's stair follows the customary limits (risers up to 7 3/4", treads of 10" or more, 2R + T between 24" and 25"), its dimension style uses round inches, and its library components are sized in whole inches. What stays metric: conductor cross-sections (`mm²`), materials' thermal properties, model fill patterns, the profile catalog's designations (`W150x13`), and expressions (component, title block and profile sketches keep the units they are written in).

Dialogs open in the middle of the window and can be moved by dragging their title; a dialog opens centered again the next time. A dialog is as wide as its buttons and its contents need.

## Commands and their tooltips

Every button in the ribbon and the quick access toolbar runs an *interface command*. So does every two-letter shortcut and every entry of the command palette. Each command defines, in one place:

- its **name** and **icon**;
- its **shortcut**: a Ctrl chord, or two letters typed while a view has the focus;
- a **description** of what it does;
- the **engine command** that makes the change. Scripts, the `ccad` command line and the MCP server call this same command (see the [automation guide](automation.md));
- whether it **can run now**, and why not.

Hover over a button to see its tooltip:

```
Move  [MV]
Moves the selected elements from a base point to a target.
Unavailable: Select the elements before using the tool
Engine command: elements_move
```

Buttons that cannot run are greyed out, and their tooltip gives the reason. Typical reasons are "nothing to undo", "select the elements first", "open a sheet to export it", "select one text note" and "copy elements first". A shortcut typed when its command cannot run shows the same reason in the status bar.

## Where commands live

Each command has one place in the ribbon tabs; the quick access toolbar, the command palette and right-click menus may offer it again. The tabs are, in order:

- **File**: a page over the window rather than a row of buttons. Down its left: Back (or Esc), New, Open, Save, Save As, *Recent Files*, *Export*, Close Project, Preferences, About and Check for Updates. On its right, *Recent Files* lists the recent projects (a click opens one) and *Export* every export format with what it writes, greyed with the reason when the active view cannot be written so, then the plugins' formats. Running a command, Esc or another tab goes back to the tab shown before.
- **Architecture**, **Structure**, **MEP**, **Massing & Site**: the tools that create model elements, by discipline. Grids live in Architecture; Structure's material (Concrete, Steel, Timber) is a segmented control at the start of the tab that picks its framing and connection groups.
- **Annotate**: dimensions, detail lines and regions, text, level marks and tags.
- **View**: creating views, schedules and sheets, view graphics, hiding and isolating, windows. *Zoom to Fit* is in each view's bar (and ZE).
- **Insert**: importing files, and loading or making reusable types: components, detail components and title blocks.
- **Manage**: the project's settings (information, units, levels), its *Standards* (materials, fill patterns, line styles, tag types, profiles, the pipe catalog), browser organization, phases, design options, macros and plugins.
- **Plugins**, while a loaded plugin adds buttons.
- **Modify**, last: editing what is selected. Selecting something with the Select tool brings this tab forward, and clearing the selection goes back to the tab shown before.

The main commands of a group are large buttons. Secondary commands whose icons do not explain themselves are medium buttons, an icon with its name beside it. Only families of familiar glyphs (move, copy, rotate, mirror, trim…) are small icon-only buttons, named in their tooltips. A family whose names are too long for the row opens as a menu from one large button with a ▾: *View → Hide/Isolate* and *MEP → Documentation*. A small arrow at the right of a group's caption (a *launcher*) opens the settings of what the group makes: *Line Styles* from Annotate's *Detail*, *Tag Types* from *Tags*, the *Pipe Catalog* from MEP's *Plumbing*.

The **quick access toolbar** starts with Home, New, Open, Save, Undo and Redo, then the user's commands: by default Export PDF, Measure, Aligned Dimension, Text, Default 3D View, Section and Close Inactive Views. Right-click any ribbon button and choose *Add to Quick Access Toolbar* (or, on one already there, *Remove from Quick Access Toolbar*). The ▾ at the end of the toolbar lists its commands, each moved left or right or removed, and *Restore defaults*. The choice is kept between sessions.

### The Modify tab and the right-click menu

*Modify* holds the edits that apply to any element: selection, clipboard, move, copy, rotate, mirror, align, trim, join geometry, paint, groups, demolish. While something is selected its title names the category (**Modify | Walls**, **Modify | Roofs**, or **Modify | Multiple** for several), on a tinted ground, and it ends with one highlighted group per selected category that has commands of its own:

| Selected | Group |
|---|---|
| Walls | Flip Walls, Attach Top, Detach Top, Edit Wall Profile, Reset Wall Profile |
| Roofs | Edit Boundary, Join Roof, Unjoin Roof |
| Floors, ceilings, pads and other sketched outlines | Edit Boundary |
| Grids | Align Grid Ends |
| Sweeps | Edit Profile |
| Text notes | Add Leader |
| Components | Edit Component |

With a sheet as the active view, a *Title Block* group holds *Edit Title Block*. These commands have no other place in the ribbon.

With the Select tool, a **right click** in a 2D or 3D view opens a menu. On an element it selects it first, unless it is already selected; the menu then offers *Select All Instances*, *Create Similar*, *Edit Type…*, the same category commands as the Modify tab, hiding, isolating and overriding graphics, and *Cut*, *Copy* and *Delete*. With nothing selected it offers *Paste*, *Zoom to Fit*, *Visibility/Graphics* and resetting temporary hiding. Each entry shows its shortcut; one that cannot run is greyed, with its reason on hover. A right drag still pans in 3D views; right clicks on tags, fitting labels and level heads keep their own menus.

With any other tool active (Wall, Door, Window, Move…), a right click opens a short menu: *Cancel* leaves the tool as pressing Esc until the Select tool is back would (what is being drawn is dropped, a spline wall is ended where it is), and *Zoom to Fit*. In a chain of dimensions a right click also ends the chain.

## Icons and badges

Icons are drawn in two tones: the strokes in the text color and the soft fills in the theme's accent tint. A small badge in the bottom-right corner marks what kind of action a command is:

| Badge | Meaning | Examples |
|---|---|---|
| green **+** | creates something new | new floor or ceiling plan, 3D view, legend, drafting view, schedule, sheet, new component |
| blue arrow down | brings data in from a file | Import IFC, Import CAD, Load component |
| blue arrow up | writes data out to a file | Export PDF, Export SVG, Export Image, Export DXF |
| red **−** | removes something | Delete |

The selected tool is highlighted in the accent color. Unavailable commands are greyed out, badges included.

## Collapsing the ribbon

To give the views more room, collapse the ribbon to its tab titles. Any of these collapses it or expands it again:

- **Ctrl+F1**;
- a **double click** on any tab;
- the **arrow** at the right end of the tab row.

While the ribbon is collapsed, a click on a tab shows that tab's panel over the views. The panel closes when a command runs, when you press Esc or click elsewhere, or when you click the same tab again. Whether the ribbon starts collapsed is set in *Preferences → Interface*.

## Narrow windows

When the window is narrower than a tab's groups, the row is compacted first: rows of large buttons become medium buttons (icon and name on one line, in columns), and if that is not enough the last groups become one large button each, named after the group, that opens its buttons as a menu. Only when every group is a menu and the row still does not fit do the groups scroll sideways: arrows appear at both ends of the row; click them to scroll, or use the mouse wheel. Each arrow is greyed out once that end is reached. Widening the window brings the groups back.

## Command palette

**Ctrl+Shift+P** opens the command palette, as does the magnifier at the right end of the tab row. Type part of what you are looking for. The search ignores case and accents ("niveis" finds "Níveis"), and every word you type must match. The palette finds:

- **interface commands**, by name, description or shortcut (typing `WA` finds *Wall*);
- **plans to create** for each level ("Floor plan: Ground floor") and **schedules** for each category;
- **views to open** ("Open view: …");
- **engine commands** (`level_create`, `elements_list`, `type_set`…), shown in a monospaced font.

Use ↑ and ↓ to choose and Enter to run, or click an entry. Esc closes the palette. An unavailable command stays in the list, greyed out, with its reason in place of the description.

### Running engine commands

Choosing an engine command opens a form with its description and its arguments in JSON, already filled with the required fields:

```json
{
  "elevation": 9.0,
  "name": "Roof deck"
}
```

**Run** (or Ctrl+Enter) executes the command in the open project and shows its result or error message. An edit is one undo step and is recorded while a macro is recording, like any other change. **Back** (or Esc) returns to the search. The arguments are the same as in scripts and in the [command reference](commands.md). Lengths are in meters, angles in degrees, points are `[x, y]`, and levels, types, views and materials can be named by id or by name. A plugin's command opens its own form instead (see [Plugins](#plugins)), except from the macro editor's *Insert Command…*.

The engine's file commands (`project_open`, `project_save`, `ifc_import`, `ifc_export`, `sheet_export`, `view_export`…) are not offered here. Their interface commands in the *File* and *Insert* tabs and the palette handle files through the usual dialogs.

**Create Similar** (CS, also *Modify → Clipboard*) starts the tool that draws the selected element, with its type: a wall's wall tool, a door's door tool, a floor's sketch, a dimension's tool in its mode (aligned, linear, angular…), a detail line's tool in its line style. Several elements selected work when they are all of one type; the selection is cleared.

Two-letter keys work while a view has the focus and no text field is being edited. The README lists them all. Each tooltip shows its own shortcut as well.

## Navigating views

In 2D and 3D views the mouse wheel zooms around the cursor and a middle (or, in 3D views, right) drag pans; a middle double-click fits the view. On a trackpad, two fingers pan and a pinch zooms; on a Mac, Cmd and two fingers zoom too. The views tell a trackpad from a wheel by the scroll it reports (points, not lines); *Preferences → Drawing & navigation → Trackpad scrolling pans* turns this off, so that any scrolling zooms (for a mouse that reports its wheel like a trackpad). The component, profile and title block editors, the visual programming editor and the site map work the same way.

## Selecting in 2D views

A click picks the element under the pointer (Ctrl adds or removes it). A drag that starts on empty paper, or inside a floor, a hatch or another fill, draws a selection box: dragged to the right it is a window and takes the elements wholly inside it (their lines, fills and texts); dragged to the left it is a crossing, dashed and green, and also takes those it cuts or lies in: a wall crossed between its ends, a floor around the box, a text anchored in it. Room areas and imported drawings are not taken by a crossing (a window around them takes them). Ctrl keeps the current selection and adds to it. A drag that starts on an element's line, or on an element already selected, moves it instead (Ctrl+drag copies).

The element under the pointer is highlighted before the click, and the status bar names it (*Category : Type*). Where elements overlap, **Tab** steps to the next one under the pointer and **Shift+Tab** back, wrapping round: first what a click takes, then the other lines by distance, then the fills topmost first, then imported drawings. Over a wall, the chain of walls joined end to end with it (stopping where three or more walls meet) comes right after it. The status bar shows the place in the list, such as *(2/4)*, and a click selects the highlighted candidate, a chain with all its walls (Ctrl adds or removes it). Moving the pointer more than a few pixels, leaving the view or changing the model starts over.

Tags of doors, windows, beams, columns and footings can be dragged to another spot with the Select tool (the pointer turns into a hand over them). The tag keeps its text and gets a leader back to its element; each plan keeps its own tag positions (a duplicated plan starts with those of the original). *Reset Tag*, in the element's properties, puts it back where it sits by default.

What is drawn in a view (detail lines, filled and masking regions, text notes, dimensions, level marks, detail components, imported drawings) belongs to it. Copied (Ctrl+C) and pasted (Ctrl+V) with another plan, elevation, section, legend or drafting view active, it goes into that view at the same coordinates, so a plot boundary or a buildable area drawn in the site plan can be reused in another plan; dimensions pasted into another plan keep measuring the same elements. From a 3D view or a schedule it goes back into its own view. In the project browser, *Duplicate with Detailing* copies a view together with what is drawn in it (*Duplicate* copies only the view).

**Dimensions follow what they measure.** A dimension whose ends lie on the lines of elements (a wall's face, a column's side, a level line in an elevation) is tied to them: when the elements move, its ends move with them. Typing a new value moves what its far end touches. In plans, a linear or aligned dimension with both ends on elements can be **locked** (the padlock beside its text when it is selected, or *Locked* in its properties; `dimension_lock`): it then keeps its value, so moving the element at one end moves the element at the other with it, and on along a chain of locked dimensions, in one undo step. An edit that would still change a locked dimension (both ends moved apart, or the other element pinned) is refused with a message.

*Annotate → Levels* places level marks. *Level in Plan* (in a floor or ceiling plan) draws a circle with two filled quarters on the clicked point and writes the finished level of the floor under it above a shelf line and the raw level of its structure (the top of the layers below its finish) under it; off any floor it writes the plan's level. *Level in Section* (in a section or elevation) draws a triangle pointing down to the point and writes its height, with the raw level when the point lies on the top of a cut floor; in a section the tool snaps to the view's lines, so a click on a floor's top line lands on it. The values follow the model; in the properties palette a mark can set either level by hand, hide the raw one or put the values on the left. The type holds the text size, the datum (the value written for the project's zero, e.g. 100.00) and the suffixes, *(N.A.)* and *(N.O.)* by default in Portuguese.

**What a click takes first.** Within reach of the pointer, a line of the model comes before a grid's or a level's, however near those are: a click on a wall drawn along a grid takes the wall, and the grid is picked where no model line is near (or with Tab). Where the outline of a floor, ceiling, roof, foundation, terrain or pad lies on another element's line (a floor's edge under a wall's face), the other element comes first. While several elements are under the pointer, the status bar adds *Tab to cycle (1 of N)* to the name of the one a click takes.

**Filter Selection.** The count of selected elements in the status bar (*3 selected*) opens the selection's filter: its categories with how many of each, checked. Unchecking a category deselects its elements and checking it selects them again; *Only* keeps that category alone. The list stays the one the filter was opened on, so a category unchecked by mistake can be checked back.

## Editing several elements

The field at the top of the properties palette (*Search properties*) keeps the rows whose name holds what is typed, case and accents aside (*estrutural* finds *Estrutural*), opening every section while it holds text; × clears it. It is kept while the app runs, for the next selection too.

With several elements of one category selected, the properties palette shows their *Type* and *Level* (*Base Constraint* for walls, columns, stairs, ramps and shafts) and the parameters they share: the walls' *Location Line*, the base offset, the *Top Constraint* (unconnected, or up to a level; walls made unconnected keep their height) with its offset or the *Unconnected Height*, sill height, overhang, rotation, *Structural*, *Room Bounding*, the walls' joins at their ends, flips, and the identity data (*Mark* and *Comments*). A value that differs among them shows *‹varies›* (an indeterminate box for on/off ones); choosing or typing one sets it on all of them in one undo step (the command `elements_set`; types through `elements_set_type`). A mixed selection shows how many of each category and *Delete*.

## Selecting in 3D views

With the Select tool, a click picks the element under the pointer (Ctrl adds or removes it). Shift+drag draws a selection box, as in plans: dragged to the right it is a window and takes the elements wholly inside it; dragged to the left it is a crossing and also takes those it touches. Elements behind others count too; hidden ones do not. Ctrl keeps the current selection and adds to it. With *Dragging in 3D views selects* on in *Preferences → Drawing & navigation*, a plain left drag draws the box and Shift+drag orbits instead.

## Modifying in 3D views

**Move**, **Copy**, **Array**, **Rotate**, **Mirror** (pick or draw the axis), **Align** and **Join Geometry**/**Unjoin Geometry** also work in 3D views; left-drag still orbits (or Shift+drag, see above), middle or right drag pans.

- Points are picked on a horizontal working plane at the level of the elements being changed; once the first point is picked, the next ones stay at its height. A square marks a snap to a model point near the pointer: a corner of an element, the center of a column or component at its base or top, a wall end, a grid crossing. A cross marks a point on the plane. Shift keeps the main axis; a typed distance and Enter work as in plans. The preview shows the elements' outline where they will go.
- Every change is a plan transform: elements keep their level. Moving a level 2 column from one of its corners to the matching corner of the column below puts it over that column.
- **Align** (AL, also in plans): click the face or line to align to, then the face or line of the element to move. While you point, the face or line a click would take is drawn thick; once the reference is chosen it shows as a red dashed line across the view, until the second click or Esc. The element moves in plan, so the two may be on different levels (a column above onto the face of the column below). Every element aligns by the face or side nearest to the click (a wall by either face, a column by a side); grids, and elements picked from the command line without a point, by their location line. When the two are not parallel, the element first turns about the point clicked until they are. In an elevation or a section, Align works by the lines drawn there: click the vertical line to align to (a wall's cut face, a beam's side), then the vertical line of the element to move, and the element moves across the view until they meet. By two horizontal lines it changes heights: a wall's or column's top or bottom, whichever line you click, rises or drops onto the reference (its other end stays), and a beam, floor, ceiling, roof, foundation or component moves up or down whole (a wall's top onto a beam's underside, a beam's underside onto a wall's top).
- **Attach Top** (*Modify | Walls*): with walls selected, click a roof, ceiling or floor in a plan, elevation or section. Under it each wall rises or drops to its underside, following its slope (a gable wall ends in a triangle up to the ridge); where it is not under it, a wall keeps its own top, and a wall straddling its edge counts as under it. The walls follow the roof when it changes, and keep their own top again if it is deleted. *Detach Top*, or the button under *Top attached to* in a wall's properties, gives them back their own top. Arc walls keep their own top. `wall_attach` does the same from the command line.
- **Join Roof** (*Modify | Roofs*, with a roof selected, in plans, elevations, sections and 3D views): the status bar asks you to pick the roof to join (the wing or bay), then the roof it meets. Only roofs are picked and highlighted; a click elsewhere is ignored. The wing's end runs on into the other roof up to the valleys and the other roof is cut away under it, in one undo step; if the roofs do not meet, the status bar says so. With one roof selected when the tool starts, it is taken as the wing and the tool asks for the second roof at once. The tool stays on after a join, ready for the next wing; Esc steps back one pick, then leaves the tool. **Unjoin Roof** (available with a joined roof selected) builds the selected roofs as drawn again, in one undo step. A roof's properties show *Joined to* with an *Unjoin* button, and say so when the roofs no longer meet and the join is not built. `roof_join` and `roof_unjoin` do the same from the command line.
- **Flip Walls** (*Modify | Walls* or the right-click menu, or **Space** with walls selected): swaps the exterior and interior sides of the selected walls. The location line stays where it is and the layers mirror about it, so a wall drawn on its exterior finish face keeps that face on the line and its body goes to the other side. Arcs and splines keep their curve; doors, windows and niches stay in place facing the same way; an elevation profile and a curtain wall's grid stay in place along it (a grid its type lays out from one end becomes the wall's own lines); the reinforcement stays on the faces looking the same way, vertical bars at the same stations; dimensions keep their points. One undo step. With the Select tool, Space flips the selected walls with the rest of the selection (components and columns turn, doors and windows flip; the doors and windows of a flipped wall go with it). While drawing walls, Space flips the side of the walls drawn next: the preview shows the body on the other side of the line. `wall_flip` does the same from the command line.
- **Trim/Extend to Corner**, **Trim/Extend to Reference**, **Split Element**, **Offset** and **Allow/Disallow Join** pick ends and sides on plan linework and stay unavailable in 3D views, with that reason in their tooltip.

## View graphics

*View → Graphics* holds **Visibility/Graphics** (VG), **Filters** and **View Templates** (also under *Manage*).

- **Visibility/Graphics** edits the active view (or, from the template manager, a template). The *Model Categories* and *Annotation Categories* tabs list each category with a visibility box and cells for projection lines, surface fill, cut lines, cut fill, halftone and transparency; a cell shows the override (— when none) and opens an editor with color, weight (paper mm) and pattern. *Walls* opens (▸) to their subcategories, one row per layer function (structure, substrate, insulation, finish, membrane), each with its own cut lines: in plans at the medium and fine levels, the lines of a cut wall's layers take their function's color, weight and pattern over the category's (an element's own override still wins). A line between two layers is the core's when either is structure, else that of the layer nearer the core; a face is its outer layer's. The *Filters* tab lists the filters applied to the view, in priority order (↑ ↓), with enabled and visible boxes and the same cells; *Add Filter…* applies another one and *Edit Filters…* opens the filter editor. When the view's template controls categories or filters, the tab says so and is read-only. OK keeps the changes, Cancel undoes them.
- **Filters** edits the project's filters: name, categories (none: all) and rules — a parameter, an operator and a value — combined with AND or OR, with the number of elements matching.
- **View Templates** lists the templates; *Create from View* makes one from the active view. Each property has an *Include* box; *Apply Properties* copies the template into the active view once, *Assign to View* makes the view follow it. The view's properties show its template (choose *None* to free it) and a *Visibility/Graphics* button; properties the template controls are read-only.
- **Detail level** (*Coarse*, *Medium*, *Fine*), in the *Graphics* section of a plan's, elevation's, section's or 3D view's properties, and a template property: at *Coarse*, layered walls, floors and roofs are cut as one plain region (no layer lines, no material patterns); at *Medium* (the default) and *Fine* they show their layers. Each component piece has *Shown at* boxes for the three levels (all checked by default), so a component can draw a simple block in coarse views and its details only in fine ones; doors and windows too.
- **Visual style**, in the *Graphics* section of every plan's, elevation's, section's and 3D view's properties, and a template property (*View default* leaves each view its usual style): *Wireframe* draws every edge, seen through the model, with no faces; *Hidden line* fills faces in white so they hide what is behind them; *Shaded* draws the same white faces and edges as hidden line, shaded grey by the light (the view's sun, else a light from the viewer's side: white where a face looks at it, a mid grey where it turns away), and the sun's shadows in a darker grey (how light the shade and how dark the shadows are is the view's *Ambient light* and *Shadow intensity*, see *Sun settings*); *Consistent colors* in the material's color, the same on every side; *Textures* in the material's appearance color with its surface pattern (*Surface Pattern* in the material browser: brick, concrete, sand, hatches…) at real size in 3D views and at the view's scale in 2D views. Plans are drawn in hidden line by default; in the shaded, consistent colors and textures styles the faces below the cut plane (above it, in ceiling plans) are filled under the plan's linework, and the wireframe drops fills and hatches. Elevations, sections and 3D views are shaded by default. `view_set` and `template_set` take `visual_style`.
- **Underlay**, a section of every floor and ceiling plan's properties and a template property: the plan of another level drawn halftone under the view's own, for reference while drawing. *Plan below* and *Plan above* take the next level below (or above) the view's, which suits templates, or a given level; *Seen from* draws it looking down, as a floor plan, or up, as a ceiling plan. Only the model is shown (no annotations), in the faint pen and with the view's category visibility; it is not picked or selected, but the drawing tools snap to its lines (ends, midpoints, crossings and points on them), and doors and windows line up with them. It is shown on screen only, unless *Print underlay* puts it on sheets and in exports. `view_set` and `template_set` take `underlay` (e.g. `{"below": {"level": "Next", "looking": "Down"}}`); deleting a level drops it from the underlays that name it.
- **Section marks** in plans follow NBR 6492 (figure A.19): at each end a 12 mm circle with the drawing's number over the sheet's (while the section is on no sheet, the last word of its name over a dash), on a filled triangle pointing where the section looks, joined by an extra-wide dash-dot line. Click a mark to select it (its properties show the section's), drag it to move it, drag its square handles to move an end, press **Space** to flip it, and **Delete** to delete the section. *Split line* in its properties draws only a piece of line next to each head; drag the round handles at the pieces' inner ends to bring them closer to their head (or set *Segment at start/end*). `view_set` takes `start`, `end` and `segments` (`[at start, at end]` in meters, or `null`). A double click on a section mark, or on an elevation marker, opens its view.
- With elements selected, **Override Graphics** changes their graphics in the active view only and **Hide in View** (EH) hides them there (shown again from Visibility/Graphics).
- **Hide/Isolate** (temporary): HH hides the selection, HI isolates it, HC and IC hide or isolate its categories, HR resets. While active, the view has a colored border and a chip with *Reset* and *Make Permanent*. Temporary hiding is not saved, not undone and not printed.

## Textures and painted faces

- **Material textures** (*Manage → Materials*, *Appearance* tab, *Texture*): *Load Image…* gives the material a PNG, JPEG, GIF, BMP or WebP picture (up to 16 MB and 4096 × 4096 pixels), kept in the project file; *Remove* takes it away. The thumbnail shows the picture; *Repeat width* and *Repeat height* are the real size of one copy of it on the faces (a new picture keeps its proportions at 1 m wide unless the size was set before), *Offset X/Y* move it and *Rotation* turns it. In the *Textures* visual style, 3D views lay it on every face of the material at that size: on floors, roofs seen from above and other horizontal faces along plan X and Y; on walls and slopes level across the face and up it. Each 3D view keeps up to 16 textures at 512 × 512 pixels with their mipmaps; a picture that cannot be read, or past the sixteenth, shows the appearance color. 2D views keep the appearance color and surface pattern. `material_texture_set` (with `path` or base64 `data`, `width`, `height`, `offset`, `rotation`) and `material_texture_clear` do the same from the command line; `material_get` shows the texture's layout and a summary of the picture (format, pixels, bytes), never its bytes.
- **Paint** (*Modify → Geometry*, PA): click a face of an element in a 3D view to paint it with the material chosen in the options bar; the face shows that material (color, surface pattern, texture, transparency) in 3D views and in elevations and sections, over the material its type gives it. The paint covers the face clicked and the faces touching it in the same plane (a wall face split around its windows), or the rest of a curved surface; painting it again replaces the paint. **Remove Paint** takes the paint off the face clicked. In 2D views the tools say to use a 3D view. `paint`, `paint_remove` and `paints_list` (with each paint's faces and area) do the same from the command line.
- **How a paint finds its face**: the model's faces are rebuilt after every change, so a paint keeps a point on the face and the face's outward normal. After a change it goes on the element's face (framing and other secondary parts left out) turned within 20° of that normal that passes nearest the point, then spreads as above. Moving, rotating and mirroring the element move the point and turn the normal with it; a longer wall or a thicker layer keeps the paint on its side. A face turned further than 20° shows no paint until it is painted again. Renaming a material renames its paints; a material used by paints cannot be deleted. Paints are kept in the project file and copied with their element; IFC export leaves textures and paints out.

## Sun settings

*View → Graphics → Sun Settings* (or the *Sun* button in a view's properties) gives the active plan, ceiling plan, 3D view, elevation or section a sun; a view without one gets the default sun when the dialog opens (an elevation or a section the conventional sun, casting shadows), and Cancel takes it away again.

- **Solar study**: *Still* is one date and time; *Single day* a study from one time to another (or *Sunrise to sunset*) every 15, 30 or 45 minutes or hour; *Multiple days* the same over a range of dates, or one frame every day, week or month; *Lighting* a light from an azimuth and altitude given by hand, measured from true north or, with *Relative to view*, from the direction the view looks along, so that it turns with the camera. A study's *Current frame* picks the moment shown; the line under the settings gives the sun's azimuth and altitude, sunrise and sunset.
- **Conventional (45°)** sets the conventional sun of façade drawings: a light relative to the view, from over the viewer's left shoulder along a cube's diagonal (azimuth 225° from the look direction, altitude 35.26°), so a shadow falls down and to the right of what casts it, as far across and as far down as it stands in front of the face the shadow falls on: the depth of a balcony, an eave or a recess reads from its shadow.
- **Presets**: the built-in ones (the solstices and equinoxes, the whole year, the solstice weeks, light from above right or left) and the project's own. *Save…* names the current settings; *Rename* and *Delete* act on the preset picked.
- **Location and time zone**: the sun stands where it does at the project's site (*Massing & Site → Site → Site Location*; without one, at the equator at Greenwich). Dates and times are local: the time zone follows the longitude (*Automatic*) or is set by hand.
- **Show sun path** draws the sun path diagram over the view: a compass ring turned to true north on the ground level, the day's path with a dot at each hour, the sunrise and sunset times, the date and the sun; a study over several days adds its first and last days. It is not picked, snapped to or cropped. In 3D views it is drawn over the model, the sunrise time in amber, the sunset time in red, the date and the current time in blue.
- **Shadows** casts the sun's shadows on the model while it is above the horizon, and on a ground plane: the plane of the level chosen in *Ground plane at level*, else of the lowest level, as in the rendered image. 3D views show them, and so do plans, elevations and sections in the shaded, consistent colors and textures styles (not in hidden line or wireframe), with exact outlines that print and export with the view. Each view casts them as it is read. A floor plan reads the site: the whole model it shows casts them, what stands above its cut plane too (upper storeys, roofs, eaves, the beams of a pergola), on the ground, terrain, decks and terraces, and under eaves, porches and garages open on a side, as the sun does; only what is indoors keeps its plain shading. A section casts them from the model beyond its cut line onto what is outdoors, the fronts, roofs and ground seen beyond, an eave's shadow on the wall under it among them; the rooms it cuts keep their plain shading. Indoors is the same in both: a space closed by walls with a floor, roof or ceiling over most of it, where it lies under one. An elevation casts them from the whole model onto everything it shows. Ceiling plans draw none. What the view hides casts and catches none, and glass and what the view's graphics make transparent cast none. Shaded elevations, sections and 3D views are lit by the sun, and by ambient light only while it is below the horizon.
- **Ambient light** and **Shadow intensity**, also in the *Graphics* section of the properties of every view that takes a sun (with a sun or not): the light of faces turned away from the light, 30% to 100% (at 100% nothing is shaded; 60% by default), and how dark cast shadows are, 0% (none) to 100% (black; 55% by default, a shadow on a white face then a 45% grey). They apply to the shaded, consistent colors and textures styles in 2D and 3D views, not to rendered images; in the textures style a shadow darkens the face's color under its surface pattern, which stays drawn. Each drag is one undo step (`view_set` `shading`).
- OK keeps every change as one undo step and Cancel undoes them; *Remove Sun* removes the view's sun. The view cube's compass shows true north.

## Render

*View → Graphics → Render* path traces the active 3D view in a window of its own: the picture on the left, the view's render settings on the right. It takes the camera the viewport shows when it opens (a camera still fitted to the model is fitted again for the render's size and field of view). *Render* starts it; the picture refines while it renders, and the line under it gives the samples done, the time taken and the scene's triangles; *Stop* keeps what is rendered so far. The wheel zooms about the pointer, a drag pans and a double click fits the picture again.

- **Quality**: *Preset* (Draft, Medium, High; Custom when the values match none), *Samples* per pixel, light *Bounces*, *Clamp* (the brightest value of a sample, against isolated bright specks; 0 turns it off) and *Clay* (every opaque surface in one white matte, lit as usual).
- **Output**: *Size* (the viewport's size, the usual video sizes or Custom), *Width × height*, *Field of view*, *Exposure* in EV and the *Tone map* (Filmic or Standard). Exposure and tone map change the picture already rendered at once, without rendering again; other changes take effect on the next *Render*, which the line under the picture recalls.
- **Environment**: *Sky strength*, *Sun strength*, *Ground color* and *Ground plane*. The sun is the view's: *Sun Settings…* opens the Sun Settings dialog on the view and comes back to the window when it closes.
- **Region**: with *Region* on, a drag on the picture draws a rectangle, and *Render* traces only that part, over the last picture when it has the same size; turning *Region* off clears it.
- **Save Image…** writes the last picture as PNG or JPEG (exposed and tone mapped as shown) or as OpenEXR or Radiance HDR (linear light).
- The settings are the view's (`view_set` `render`, `view_get`): changing one writes it, and everything changed in the window is one undo step; *Close* keeps it. `view_render` renders a view to a file without the window.

## Sketching outlines

Floors, ceilings, roofs, foundation slabs and masses are sketched in a plan. Their tool opens a sketch, as the Wall tool opens *Modify | Place Wall*: the ribbon brings forward the contextual *Modify | Create Boundary: Floor* tab (or *Edit Boundary: …* for an existing element) with Select, the Modify tools, the highlighted *Draw* group (lines, rectangles, polygons, circles, ellipses, arcs, splines, plus what this sketch adds: *From Walls* for what stands on a level, *Points* for a terrain) and the *Mode* group with *Finish* (green) and *Cancel* (red). The other tabs wait, greyed, until the sketch is finished or cancelled, and the tab shown before comes back.

- **Draw**: lines (chained until the loop closes; *Chain* in the options bar), rectangles, inscribed and circumscribed polygons (*Sides* in the options bar), circles, ellipses, arcs by three points, by their center, tangent arcs that continue the free end of a line or arc, and splines: smooth curves through the points clicked (click the last point again, double-click or press Enter or Esc to end one; click its first point to close it). A spline's grips are the points it passes through, which take their handles along, and the handles, which keep it smooth. Points snap to the model and to the sketch's own ends, middles and centers. *From Walls* adds lines along the walls of the level, on the face chosen under *Wall face* in the options bar: a finish face or a core face (the wall's structure layers, inside its plaster), exterior or interior, the core's center or the centerline. Exterior is the side outside the loop of walls, and each side of the outline goes to that face of its own wall, so a slab can stop at the core while the finishes run past it. The default is the exterior finish faces (the interior ones for ceilings). Changing *Wall face* afterwards moves the lines *From Walls* added to the new face, except those moved, trimmed or deleted since (one undo step). `floor_create`, `ceiling_create`, `roof_create` and `foundation_slab_create` take the same choice as `wall_face` with `from_walls`. After the first point, type a value and press Enter: a line's length (Tab switches to its angle), a rectangle's width and, after Tab, its depth, a circle's or polygon's radius, the distance of *Move* and *Copy*; the value runs towards the cursor, Backspace edits it and Esc drops it.
- **Select**: a click picks a curve (Ctrl adds or removes), a double click the chain of curves joined to it, a window the curves inside it (dragged to the left, those it touches); its grips stretch it (an end drags the ends joined to it, so loops stay closed; an arc's middle grip changes its bulge, a circle's and an ellipse's grips their radii). The properties palette shows the picked curve's start, end, center, radius, semi-axes and rotation, to type them. Delete removes the picked curves; Ctrl+Z and Ctrl+Y undo and redo the sketch's own changes.
- **Modify**: *Move*, *Copy* (*Multiple* places copies from the same base point), *Rotate* (center, reference and final direction, or a typed angle and *Apply*) and *Mirror* (across a line of the sketch, or an axis drawn with two points; *Copy* keeps the originals) act on the picked curves. *Offset* copies the curve under the cursor *Distance* away on the side clicked; with *Chain* the whole chain of joined curves is copied, neighbors meeting where their copies cross (ellipses have no offset). *Trim/Extend to Corner* makes two curves meet, keeping the parts clicked; *Trim/Extend to Reference* takes a reference curve, then trims or extends each curve clicked to it; lines run on along their line, arcs round their circle. *Split Element* cuts a curve in two where it is clicked (a circle or a whole ellipse into halves, which can then be trimmed). The two-letter shortcuts of these tools work in the sketch too.
- **Finish** makes the element. Loops inside the outline become openings of floors and roofs. A sketch that is open, branches or crosses itself stays open, with the place marked and the reason in the status bar.
- **Edit Boundary** (*Modify*, in the selected category's group, or the right-click menu) opens the sketch of the selected floor, ceiling, roof or mass: its curves as drawn, or lines along its outline. Moving, rotating and mirroring the element keeps its curves; editing its points directly drops them.

## Roof coverings and framing

A roof type sets its **covering** and its **framing**, in the type dialog's *Covering and Framing* section.

- **Covering**: ceramic tiles (colonial, French, Roman, Portuguese), concrete tiles, corrugated fiber cement, trapezoidal metal sheets or sandwich panels. Each comes with reference figures: the least slope it takes, its weight per m², tiles per m², the batten gauge and the widest span between purlins. They are typical values from public product data, for early design; the manufacturer's prevail.
- **Framing**: *Timber* puts battens right under the roof at the tile's gauge, rafters down the slope under them (at the rafter spacing) and purlins along the eaves under the rafters, spread evenly from eave to ridge no farther apart than the purlin spacing (or the covering's span, when smaller). *Timber trusses* adds trusses under the purlins, across the ridge and no farther apart than the truss spacing: top chords along the roof faces, a level tie, a king post under the apex and struts to the middle of each chord. *Steel* puts purlins only, right under the sheets. Sizes, spacings and material are set on the type. Choosing a covering picks the framing it usually lies on, if none was chosen.
- The framing follows the roof's sloped faces, whatever its shape, and shows in 3D views, elevations and sections in its material. It is not part of the roof's own volume. IFC export writes each member as an `IfcMember` in the roof, and importing that file brings the covering and framing back on the roof's type.
- A roof's properties show the covering, its slope against the covering's least (in red when below), the number of tiles, the weight and the framing's lengths and volume. Roof schedules can list *Slope*, *Tiles*, *Weight*, *Framing Length* and *Framing Volume*. The `roof_check` command returns the same, with the rules the roof breaks.

## Conceptual masses

*Massing & Site → Massing → Mass* (`MS`) sketches an outline in a plan, like a floor, and extrudes it up to the level above. Masses are for massing studies before walls and floors exist: see-through bodies in 3D views, elevations and sections, cut in the plans they cross.

- **Properties**: the base offset and the height, and whether the mass is an extrusion or a loft (a top outline different from the base, made with `mass_create` and `top` or `top_inset`).
- **Mass floors**: one box per level the mass spans, with the area of the floor at that level. Plans draw the floor of their level with its area; the properties and the *Masses* schedule give the gross floor area (the sum of the floors), the number of floors and the volume.
- **Push/Pull** (*Massing → Push/Pull*, `PP`, in a 3D view): click a face of a mass, then move the pointer along the arrow (or type the distance) and click or press Enter. The top changes the height, the bottom moves down or up, and a side of an extrusion moves out or in, the sides beside it keeping their directions (a loft's sides stay; push its top or bottom). A mass with a floor at every level it spans gets the floors of the levels it reaches. Esc lets go of the face.
- **From the mass to the building**: with masses selected, *Massing → Walls by Face* puts a wall on each side of an extrusion (exterior face on the mass's face, as tall as the mass, joined at the corners), *Floors from Mass Floors* a floor on each mass floor (the mass's outline at that level, its top at the level) and *Roof by Face* a flat roof on the top. The walls, floors and roof are ordinary elements: change their types, heights and shapes as usual. A loft's slanted sides take no walls.
- Moving, rotating, mirroring, copying and pasting work as for other elements. Deleting a level removes its mass floors. IFC export leaves masses out.

## Terrain

*Massing & Site → Site → Terrain* (`TS`) sketches the terrain's boundary in a plan, like a floor's outline, and places its measured points: *Points → Point* clicks a point at the elevation set in the options bar (above the level), and undo takes points back like curves. *Finish* triangulates the points with the boundary; the boundary takes the elevations the points give it, points beyond it included, and the earth closes down to a flat base. A project without a terrain type gets one, cut in an *Earth* material (a woven hatch).

- **Plans** draw the terrain of their level: contour lines below the cut plane (every fifth a heavier major one) and, where the cut plane crosses the surface, the earth above it hatched and outlined as cut. Elevations, sections and 3D views show the solid, and sections cut the earth in its material.
- **Properties**: the base depth, the lowest and highest elevations, the area and volume (also in *Terrain* schedules), any warning (too few points, points on one line, a boundary that crosses itself), and the points themselves, whose x, y and z are edited in place or removed. *Edit Boundary* reopens the sketch with its points to change the boundary or add points. The type sets the material, the contour interval and how often a major contour comes.
- IFC export writes an `IfcGeographicElement` (`TERRAIN`); importing that file brings the terrain back with its points.

*Massing & Site → Site → Building Pad* (`PD`) sketches a pad's outline on the terrain of the plan's level, at the *Elevation* of the options bar; without a terrain there the button says so. *Finish* grades the terrain: flat inside the outline, a cut slope where the ground stands above the pad and a fill slope where it lies below, out to where they meet the existing ground (the daylight line).

- **Plans** draw the pad's outline with its elevation, ticks across its slopes (long and short in turn, the short ones from the top of the slope), the daylight line, and the existing ground's contour lines dashed where the pad changed it. Sections cut the graded earth and dash the existing ground line.
- **Properties**: the elevation, the cut and fill slopes (*By type*, or the pad's own ratio, shown as 1:n), the area, the cut and fill volumes and the net, any warning (the slopes reach past the terrain), and *Edit Boundary*. The type sets the two ratios. Pad schedules list the elevation, area and volumes, with totals.
- The pad moves and is deleted with its terrain. IFC export keeps its pads in the terrain's `ConstructCAD_Pads` property set, which import reads back.

## Railings and their hosts

Curtain walls are walls of a curtain type (a project without one gets one from the wall tool's type list: *+ Curtain Wall*). Their type properties set the vertical and horizontal grids (layout, spacing or number, justification), the panel (glass, solid, empty, or a door, window or other component) and the vertical, horizontal and border mullions. *Architecture → Build → Curtain Grid* edits one wall's grid by clicking it in a plan, elevation or section: *Add Line* (vertical or horizontal; plans add vertical ones), *Remove Line* (the nearest), *Merge/Split Segment* (the piece of a line between two others: the cells on both sides become one panel, or two again) and *Swap Panel* (the panel chosen in the options bar, or the type's again); hovering shows what a click does. A selected curtain wall's properties show its cells, panel count, glazed area and mullion length, and *Reset* puts back the type's lines or panels.

*Architecture → Circulation → Railing* (`RA`) draws a railing along the points you click, at its level plus the base offset. A railing can also follow a stair or ramp (its host): it runs along the host's side at the pitch of the nosings or of the slope, turns at its landings, and moves, changes and is deleted with it.

- **On a stair or ramp**: tick *On a stair or ramp* in the railing tool's options bar, then click a stair or ramp in a plan. The railing goes on the side nearest the click, or on both with *Both sides*. A stair's or ramp's properties also have *Add railings* for both sides at once.
- **Side and host**: a hosted railing's properties show its host and its *Side* (walking up), which can be switched. *Detach from Host* makes it an ordinary railing that keeps the path it has in plan.
- From the command line or MCP: `stair_railings_add` (with `near` for the side nearest a point) and `railing_host_set` (put an existing railing on a stair or ramp, on the side its path runs along unless `side` is given; change its side or inset; or `detach` it).

## Niches

*Architecture → Build → Niche* places a niche: a recess in one face of a wall, hosted like a door or a window but not opening the wall through. Click a wall in a plan (or in a 3D view) and the niche goes in the face on the side clicked. New projects carry a niche type, 60 × 60 cm and 10 cm deep with its bottom 90 cm above the wall's base (2'-0" × 2'-0" × 4" at 3'-0" in imperial projects); in an older project without one, the first niche brings that type. The *Sill Height* field of the options bar shows the type's sill and sets the height of the niches placed next, as for windows.

- A niche type is a component with *Width*, *Height*, *Depth* and *Sill* parameters, edited in its **Type Properties**; `niche_type_create` makes one with given sizes. In a wall thinner than the depth plus 1 cm the niche stops 1 cm short of the other face: an opening through a wall is a door or a window.
- The properties palette has the niche's distance along the wall and its sill; *Turn* (or `flip_facing`) moves it to the wall's other face. It follows its wall when the wall moves and goes with it when the wall is deleted.
- The wall keeps standing behind the niche: it is not split, and rooms, joins and wall framing ignore it. Plans show a niche the cut passes through as an open face with its sides and back, and dash one wholly below or above the cut; elevations, sections and 3D views show the recess, which also picks the niche.
- The wall's volume is less the niche's. A schedule of the *Niches* category lists each one with its size, sill, host and the volume it takes out.
- IFC export writes a niche as an `IfcOpeningElement` of predefined type `RECESS`, as deep as the niche, voiding its wall (`IfcRelVoidsElement`), with its sizes in the `ConstructCAD_Niche` property set. Import does not read niches back yet.
- A niche that would overlap a door, a window or another niche of its wall cuts nothing. Niches are rectangular; arched tops, and pieces of their own (a shelf, a lining), are not available yet.

## Shafts

*Architecture → Floors & Roofs → Shaft* (`SF`) sketches the outline of a vertical opening (a duct chase, a lift or stair shaft, a light well) in a plan, like a floor's outline; it rises from its level to the highest level above (or a level or height set in its properties). A project without a shaft type gets one the first time.

- **What it cuts**: every floor, ceiling and roof it passes through, where its outline lies inside theirs and clear of their own openings. The cuts follow the shaft when it moves, changes or is deleted, in the same undo step; plans, areas in schedules, 3D views and IFC export show them like any opening. A shaft across the edge of a slab does not cut it.
- **In plans**: its outline crossed by two diagonals, in the plan of its level and in every plan whose cut plane it passes through.
- **Properties**: the base offset, the top (a level plus an offset, or unconnected with a height), its height and area. *Edit Boundary* opens its outline again. `element_get` lists the elements it cuts (`derived.cuts`).

## Swept profiles

*Architecture → Model → Sweep* (`SW`) carries a profile along a path drawn in a plan: baseboards, crown moldings, fascia boards, gutters, copings. A project without a sweep type gets one the first time (a baseboard 1.5 × 10 cm).

- **Drawing**: click the points of the path; Enter, a double click or *Finish* ends it, and Backspace removes the last point. The options bar sets the height of the path above the level, *Closed path* (it runs back to the first point, around a room, with no ends) and *Flip side*.
- **Which side**: the profile is drawn in its own plane, square to the path: x across, to the left of the path walking along it, and y up from the path's height. *Flip side* puts it on the right; a mirrored copy keeps it on the same side of the wall it follows. Corners are mitered.
- **Profiles**: the type holds the profile and the material. `sweep_type_create` makes a type from points `[x, y]` or from `curves` (lines, arcs, circles, rectangles… making one closed outline, so a cove or a half-round gutter is drawn with arcs), and `sweep_profile_set` redraws a type's profile; both are in the command palette. A profile must be a closed outline that does not cross itself.
- **Edit Profile** (*Modify | Sweeps*, with one sweep selected, or the button in its type's *Edit Type…*) opens the type's profile in a sketch that takes the place of the views: its plane has x across (outward, to the left of the path) and y up from the path, the path's point marked where the axes cross. The sketch has the usual ribbon, drawing and Modify tools, grips and undo; points snap to the sketch's own points, the path's point, the axes and millimeters. *Finish* redraws the profile of every sweep of the type in one undo step (an open or crossing outline is refused and shown), *Cancel* leaves it as it was. The type keeps the curves, so a cove's arc is still an arc when the profile is edited again; changing the profile's points another way drops them.
- **Views**: plans and ceiling plans draw what the cut plane cuts and what lies below (or above, in ceiling plans), elevations, sections and 3D views show the solid, legends show the profile's section, and schedules list the length and volume. IFC export writes them as coverings of type `MOLDING`.

## Wall profiles

A straight wall's face can be drawn in its own elevation, so its base and top need not be level: a top that follows sloping ground, a stepped base, a gable end, an arched top.

- **Edit Wall Profile** (*Modify | Walls*, or the *Profile* section of a wall's properties) opens the selected wall's profile in a sketch that takes the place of the views: u runs along the wall from its start (at the left), z up from its base. A wall without a profile opens on its rectangle. The wall's ends, base and top are drawn as reference lines, the levels near it as dashed lines with their names, and its doors, windows and niches faintly, since the outline must hold them; points snap to all of them, to the sketch's own points and to millimeters. The sketch draws lines, rectangles and arcs, with the usual Modify tools, grips and undo.
- **Finish** gives the wall the profile in one undo step; an outline that is open, runs past the wall's ends or that a vertical line crosses more than twice is refused, with the place marked, and the sketch stays open. When doors, windows or niches no longer fit inside it, the status bar says how many: they stay in the model but cut nothing. *Cancel* leaves the wall as it was.
- **Reset Wall Profile** takes the profile off: the base and top are level again. The *Profile* section shows *Rectangular* or *Custom*.
- Arc and spline walls, curtain walls, walls whose top is attached to a roof and framed walls take no profile: the commands are disabled and their tooltips say why. Double-clicking a wall does what it did before.

## Spline walls

The wall tool (*Architecture → Build → Wall*, `WA`) opens the **Modify | Place Wall** tab, whose highlighted *Draw* group holds its modes (Esc or another tool goes back to the tab shown before): *Line* chains straight walls, *Arc* takes the start, the end and then a point on the arc (or a typed radius + Enter), and *Spline* draws one wall along a smooth curve through the points clicked. The shape modes make several walls joined end to end at once, in one undo step: *Rectangle* (two corners: four walls), *Inscribed* and *Circumscribed Polygon* (the center, then a corner or the middle of a side; *Sides* in the options bar), *Circle* (the center and a point: two half-circle walls; with a *Radius* in the options bar, one click), *Center-Ends Arc*, *Tangent Arc* (from the free end of a wall), and *Ellipse* (the center, an axis end, the other axis: spline walls). *Fillet Arc* picks two straight walls and rounds their corner with an arc wall of the options bar's *Radius*; *Pick Lines* puts walls along the detail line or grid clicked (with *Chain*, along the detail lines joined to it). In the shape modes the options bar also has *Offset* (the walls lie that far from the shape: outside a closed one, to the left of an open one; negative the other way), a *Radius* that rounds the corners of rectangles and polygons, and *Join* (off: the walls' ends stay square). `walls_create` and `wall_fillet` do the same from the command line.

- **Drawing**: click the points the wall passes through (they snap like any wall point; after the first one a typed length + Enter places the next). Click the last point again, double-click or press Enter or Esc to make the wall, in one undo step, as Esc ends a chain of straight walls; Backspace takes back the last point, and the next Esc leaves the tool. The tool stays on for the next wall. While drawing, the preview shows the wall's faces and its length; a curve that bends too tightly for the wall's thickness, has a corner or crosses itself is drawn in red with the place marked and the reason beside the cursor, and Enter then leaves the wall unmade and says why in the status bar (Esc says why too and drops the points).
- **Editing**: a selected spline wall has a grip on each point it passes through; dragging one moves it with its handles (the curve keeps its direction there), in one undo step, and a curve that would make no wall is refused with the reason. The end grips stretch the curve's ends. Split cuts the curve where it is clicked and Offset copies it along the curve; the properties show its length (no arc angle).
- Doors, windows and niches are not placed in spline walls yet (their tools say so over one), and trim, extend, align, an elevation profile and an attached top refuse them. A curved spline wall is no mirror axis.

## Strip footings and ground beams

*Structure → Foundation → Ground Beams Under Walls* places a strip footing under each selected wall (or every wall of the plan's level) along the wall's body centerline, its top at the wall's base; walls that already have one are skipped. An arc wall gets an arc strip that follows its curve (concentric with the wall), not a chain of straight pieces, so the foundation plan shows the curve and its radius and the concrete volume is exact.

- **Drawing**: the *Structure → Pad Footing* tool (`FT`) with a strip footing type picked in the options bar's type list draws strips as walls are drawn: *Line* chains straight strips (type a length + Enter; Backspace or Ctrl+Z takes back the last one), *Arc* takes the start, the end and then a point on the arc, or a typed radius + Enter.
- **Joins**: strips meet at corners and tees like beams; an arc strip meets a straight one or another arc where their faces truly cross. An arc too tight for the strip's width is refused.
- **Properties**: *Arc angle* bends a strip (0 makes it straight); its length along the arc, radius, area and volume are shown. A mirror turns an arc the other way; moving and rotating keep it.
- **Curvature handle**: a selected arc strip shows a round handle at the middle of its arc, as arc walls do; dragging it bends the strip through the pointer, its ends staying (the radius and length show while dragging). While a strip type is chosen, the options bar names the tool *Strip Footing*.
- **Beam on the footing**: a strip footing type can be an inverted T. In its *Edit Type…*, *Beam on the footing → Inverted-T section* adds a beam on top of the footing slab: the type's thickness is then the footing's at the faces of the beam, *Edge thickness* its thickness at the edges (less makes the top slope: a haunch), and *Beam width* and *Beam height* size the beam (a height of 0 leaves a sloped footing with a flat middle). The top of the footing is the top of the beam. The section runs along arcs too, with its exact volume, and shows in sections, 3D views and legends; plans add the two faces of the beam.
- **Reinforcement**: a strip's properties have a *Reinforcement* section; *Typical Reinforcement* gives it bars across and along the footing in its bottom and top layers, and a haunched strip stirrups and two top bars for its beam. `strip_rebar_create` (command palette) sets the spacings (`transverse_spacing`, `longitudinal_spacing`), the `layers`, and the beam's bars (`beam`: `top`, `bottom`, `sides`, `stirrups`). Bars across an arc strip are radial; a top one follows the slopes, runs flat between the faces of the beam and turns down to the bottom layer at each edge. Bars along it are ring bars, each as long as the arc at its own radius, following the slopes; the stirrups run over the full height of the section in the width of the beam.
- **Views**: plans dash strips below the cut plane and hatch those it cuts, the arcs as short chords; sections cut the curved body; schedules list the length along the arc and the exact volume. IFC export writes an arc strip as an `IfcFooting` (`STRIP_FOOTING`) whose body is its outline of true arcs extruded. IFC import brings strip footings, straight or arc, back as components with their mesh, as before.

## Arc beams

The *Beam* tool has two modes in the options bar, as the wall tool has: *Line* draws straight beams, *Arc* takes the start, the end and then a point on the arc, or a typed radius + Enter. An arc beam is level (it has no end elevation offset).

- **Joins**: an arc beam frames into the structural columns at its ends, each of its sides stopping where it leaves the column, and meets other beams at corners and tees like a straight one. An arc too tight for the beam's width is refused.
- **Properties**: *Arc angle* bends a beam (0 makes it straight); its length along the arc, radius, cut length and volume are shown. The volume is exact, not that of the chords the body is drawn with.
- **Editing**: a selected arc beam shows the round curvature handle at the middle of its arc; the Modify tools trim, extend, split and offset it on its circle, and a mirror turns it the other way. Tools snap to its ends, its middle and the arc.
- **Reinforcement**: top, bottom and side bars follow the arc, each as long as the arc at its own radius (so the schedule's lengths and weights match a hand calculation), and stirrups are radial, spaced along the beam's axis.
- **Views and IFC**: plans draw both faces of the arc; sections, elevations and 3D views show the curved body. IFC export writes a rectangular arc beam as its outline of true arcs extruded, with its axis on the arc, and import brings it back as an arc beam; an arc beam of another profile is written as a faceted body.

## Beam reinforcement

*Typical Reinforcement* in a beam's or column's properties gives it bottom and top bars and stirrups. Further sets are made with `rebar_create` (command palette), and each set's count or spacing is edited in the *Reinforcement* section. Stirrups are closed by two hooks at one corner (135° with straight ends of 10 bar diameters, counted in their length); a selected stirrup set's properties show *Stirrup Hooks* (none, 90° or 135°) and *Hook Tail* (bar diameters).

- **Layers**: top and bottom bars that do not fit side by side, keeping a clear distance of the bar diameter and at least 2 cm, go in a second layer above the bottom bars or below the top ones (up to four layers).
- **Side bars**: *Add side bars* puts one bar on each side face at mid height; `rebar_create` with the `sides` layout takes a `count` per face, or a `spacing` that puts as many as keep them that far apart over the height.
- **Lap splices**: a bar along a beam longer than the stock length (12 m, or 40' in imperial projects) is made of the fewest equal pieces, lapping by 40 bar diameters, and the splices of neighbouring bars are staggered by half a piece. `rebar_create` takes `max_length` (0 keeps whole bars) and `lap`. Schedules count and measure the pieces.
- **Anchorage into supports**: *Anchor into Supports* in the properties of a beam's top, bottom or side bars runs them on into the columns and pile caps the beam frames into, up to the support's far face less the cover and at most 40 bar diameters (`rebar_create` `anchor` takes another length). *Anchorage Hook* (none, down, up or automatic: top bars down, bottom bars up) bends top and bottom bars by 90° where the support is too shallow for the straight length. Between two beams in line, the bars of both lap inside the support. The anchorage counts in the bars' length.

## Column sections and their reinforcement

A structural column (the *Structural* checkbox of its properties) has a *Base support* row in the same section: *Fixed* (the default) or *Pinned*. It is the support the analytical model and its export give the column's base: fixed holds the translations and rotations, pinned only the translations.

A column type's section is a structural profile. Besides the standard shapes, the Profile Manager (*Manage → Profiles*) has *Annular sector*: the piece of a ring between an inner radius and an outer radius turning by an angle, as the columns that continue a cylindrical wall have (an inner radius of 0 makes a circular sector). The section is drawn symmetric about its vertical axis with the outer face up, and placed by the middle of its bounding box; turn each column on the circle with its rotation. Its area and the column's volume are the ring's, not those of the chords it is drawn with. L, T, U and other polygonal columns are sketched profiles (a new profile of the *Sketch* shape).

`rebar_create` (command palette) reinforces a column of any section:

- **Bars by face**: `perimeter` with `faces` takes the number of bars on each face of the section (its two corner bars included; the corner bars are shared between faces), in the order of the `derived.faces` that `element_get` lists for the column: counter-clockwise, an annular sector's outer arc first. On a curved face the bars stand at even angles. `face_spacing` puts on every face as many as keep them that far apart. A plain `count` is spread around the section, the corners first.
- **Ties**: `stirrups` follow the outline of the section the cover inside it, a curved face as a curve, and their length is the true one.
- **Cross-ties**: `ties` adds, every `spacing` up the column, a straight bar with a 135° hook at one end and a 180° hook at the other from each bar between corners to the bar opposite: straight across the section, or between the radial sides of a sector square to its axis. A tie whose line would leave the bars (between the radial sides of a thin ring) is not made.
- **Lifts**: with `max_length` the vertical bars are cut in equal lifts no longer than it, each lapping the next by `lap` (default 40 bar diameters), all at the same heights.
- **Every column of the type**: `same_type` gives the set to the other columns of the host's type in the same step.

## Wall reinforcement

A structural wall (the *Structural* checkbox of its properties) shows a *Reinforcement* section. *Typical Reinforcement* gives it horizontal and vertical bars every 15 cm near both faces; each set is then listed with its spacing, which can be edited, and a *Remove* button. `wall_rebar_create` (command palette) sets everything else, for the given walls or every structural wall of a level:

- **Faces and covers**: `faces` is `both`, `exterior` or `interior`; `cover_exterior` and `cover_interior` give each face its own cover (a tank's wet and dry faces). The bars lie inside the faces of the wall's structural core, so finishes are not counted.
- **Horizontal bars**: a `spacing`, or `zones` of spacing by height from the base, closest at the bottom. In an arc wall they are ring bars: each follows the arc at its own radius and is exactly that long in schedules.
- **Vertical bars**: a `spacing` along the wall's centerline (an even angle in an arc wall), from `from` to `to` above the base, starting `offset` after the wall's start: a second call with half the spacing as `offset` and `to` 1.5 adds the additional bars of the bottom 1.5 m between the main ones. `bottom` and `top` bend the ends: `across` the wall (towards the outside of the bar's face when positive), then `along` the bar (back beside it when positive), so `{"across": 0.12, "along": 0.60}` at the bottom turns the bar 12 cm into the slab and 60 cm up again.
- **Layers**: `outer` says which family is nearest the faces (`horizontal` by default); the other lies inside it.
- **Ties**: `ties` puts a hooked bar across the wall at every n-th horizontal and every m-th vertical bar of the exterior face.
- **Openings, joints and splices**: bars stop the cover clear of doors, windows and free ends; horizontal bars run to an end joined to another wall, where that wall's bars begin; bars longer than `max_length` (default 12 m) are lap spliced by `lap`, neighbouring splices staggered.

## Slab reinforcement

A structural floor (the *Structural* checkbox of its properties) or a foundation slab shows a *Reinforcement* section. *Typical Reinforcement* gives it a mesh every 15 cm in its top and bottom layers, and trimming bars around its openings; each set is then listed with its spacing and a *Remove* button. `slab_rebar_create` (command palette) sets everything else, for the given slabs or the structural floors and foundation slabs of a level:

- **Mesh**: straight bars in two directions, the first at `angle` (the outer layer) and the second square to it, with `spacing` and `cross_spacing`, `type` and `cross_type`; `layers` is `both`, `top` or `bottom`.
- **Radial**: `layout` `radial` makes ring bars `spacing` apart around `center` (the middle of the slab by default) and `radial_count` radial bars from the radius `start` to the edge; with `intermediate`, a shorter bar from that radius runs between each two.
- **Clipped to the slab**: every bar ends the cover inside the slab's edge and clear of its openings and shafts. Where the boundary was drawn with arcs or circles the bars end on the true curve, so in a circular slab each bar of a mesh has its own exact length; `element_get` lists a set's `derived.bars` by length.
- **Edge ends**: `hook` bends the ends of mesh bars at the slab's edge: towards the middle of the slab when positive (down for top bars, up for bottom ones), out of it when negative (into the wall above or below).
- **Splices**: bars longer than `max_length` (default 12 m) are lap spliced by `lap`, neighbouring splices staggered; a ring cut from stock is pieces that each lap the next around it.
- **Openings**: a slab with openings gets trimming bars in each layer: two bars along each side of every opening, reaching 40 bar diameters past it, and a diagonal across each corner. `trim` changes the count, spacing, anchorage and diagonals, or turns them off (`false`).

## Pile cap and pile reinforcement

A pile cap's and a pile's properties show a *Reinforcement* section. *Typical Reinforcement* gives a cap bottom bars over its piles, a top mesh and side bars (and, in a cap of two piles or of a line, stirrups), and a pile bars around its section projecting into the cap and a spiral (round piles) or ties (square piles); each set is then listed with its count or spacing and a *Remove* button. *Structure → Reinforcement → Pile Cap Reinforcement* and *Pile Reinforcement* do the same for the selected caps and piles (a selected cap's piles too), or for those of the active level that have none. `pile_cap_rebar_create` and `pile_rebar_create` (command palette) set everything else:

- **Bottom bars**: in a cap of three piles, a band of bars between each two piles along the sides of the triangle; in a cap of four, a band along each side of the square, and with *Diagonal Bands* across its diagonals; each band as wide as a pile. In a cap of two piles or of a line they run along the piles across the cap's width; a single-pile, round or ring cap gets a mesh (*Mesh Spacing*). They lie on the piles' heads, and *Bent Ends* turns their ends up the side faces.
- **Following the type**: the bars are laid out from the cap's layout, so changing the type's layout lays them out again for the new one (bands of a triangle become a square's); a pile the change adds takes the reinforcement of the cap's other piles, and a pile it removes takes its own along.
- **Piles**: *Reinforced Length* (0: the whole pile) and *Projection into Cap* (at most to the cap's top less the cover). A spiral is measured along its coil, and the bending schedule writes it as `spiral R=… p=… L=…`.

## Structure by material

The *Structure* tab starts with a *Material* group: *Concrete*, *Steel* and *Timber* buttons (one is always on; the choice is kept between sessions). The material swaps the groups made for it: concrete shows *Structure* (Column, Beam, Floor) and *Reinforcement*; steel shows *Structure* (Column, Beam, Bracing), the *Framing* grid group (Columns at Grids, Beams on Grids, Beams Between Columns, Grid Frame, Truss, Steel Building, Light Steel Frame) and *Connections* (Base Plate, End Plate, Fin Plate); timber shows *Structure* (Column, Beam, Bracing), the same grid group with Wood Frame in place of Steel Building and Light Steel Frame, and *Connections* (Bolted Joint, Hanger). Profiles, Foundation, Analytical, Documentation, Datum and Selection show for every material.

The Column and Beam buttons start their tools on a type of the chosen material, and the options bar's type list shows only those types. When the project has none, one is created from the catalog in one undo step: a W200x26,6 for steel, an MLC 9x32 glulam for timber, a 20x40 concrete rectangle for concrete (`structural_type_for`). The grid commands of the tab use the chosen material's type as well. A type's material comes from its profile (steel and cold-formed profiles are steel).

*Grid Frame* (*Structure → Framing*, available with two or more grids) opens a dialog that places columns on every storey and beams on every level of a range, in one undo step: *Base level* and *Top level*, the *Column type* and *Beam type* (of the chosen material), and *Secondary beams* with the grid they run parallel to and their *Spacing*. It frames the selected grids, or all of them when none is selected. Columns are attached to the level above, and spans and columns already modeled are skipped. Secondary beams fill each bay (four grid intersections) at most one spacing apart and end on the crossing beams; bays that are not such quadrilaterals are skipped. A run of more than 2000 members is refused. The status bar reports what was placed and skipped.

*Steel Building* (*Structure → Framing*) opens a dialog that makes a portal-frame shed in one undo step: the *Span* between column axes, the *Eave height*, the roof *Slope* and shape (gable or mono), the number of *Bays* and the *Bay spacing*, the *Column type* and *Rafter type* (of the steel material; *Catalog default* creates one), and *Purlins* and *Girts* with their type and spacing (each can be turned off). The members are ordinary columns and beams, so they get tags, schedules, 3D views and IFC export like any other; the building itself shows in plans as a dashed footprint. Selecting it shows its parameters in the properties palette (*Span*, *Eave height*, *Bays*, *Bay spacing*, the types, *Purlins*, *Girts*, *Members* and *Detached members*); changing one regenerates the members in place, keeping their ids, marks and comments. A member you edit by hand (moved, retyped or deleted) is detached and is not regenerated; *Reset Members* in the palette makes the building manage every member again. Deleting the building deletes its members, and copying it makes a new building with its own members.

*Bracing* (*Structure*, steel and timber) braces one bay of a frame, storey by storey. With two columns selected it braces the bay between them, taking their base and their common height (divided by the *Storeys*); otherwise it is a tool: click the axes of the bay's two columns. The options bar sets the *Pattern* (X, diagonal, V, chevron or inverted V, and K, whose four braces run from the mid-height of each column to the middle of the bay at the top and bottom of the storey), the *Storey height* and the *Storeys*; a diagonal also has *Flip diagonal* and *Alternate diagonals* (a zigzag up the storeys). The braces are ordinary beams of a catalog type of the tab's material (an SHS 100x100x4 tube for steel, a 6x12 piece for timber), so they get tags, schedules, 3D views and IFC export; the bracing itself shows in plans as a dashed bay line. Selecting it shows its parameters and the *Brace type* in the properties palette; changing one regenerates the braces in place, keeping their ids. A brace you edit by hand is detached and is not regenerated; *Reset Members* makes the bracing manage every brace again. Deleting the bracing deletes its braces, and copying it makes a new bracing with its own.

*Truss* (*Structure → Framing*, steel and timber) is a tool: click the two ends of the span line. The options bar sets the *Shape* (flat, mono-pitch or gable), the *Pattern* (Pratt, Howe, Warren, and for gables king post, queen post and Fink), the *Height* (chord to chord, or the rise), the *Panels* (auto aims at one per 1.5 m; a gable takes an even count), the *Copies* and their *Spacing* to the left of the span line. Its types come from the tab's material (a catalog chord and web for steel or timber). Each chord is one continuous beam (two top chords on a gable); the posts are cut to stand between the chords, or inside them when the chords are channels open toward the web, as the steel defaults are; and a truss that ends on a post has its chords run on over it and that post turned to close the end. The chords, diagonals and posts are ordinary beams and columns, so they get tags, schedules, 3D views and IFC export; the truss itself shows in plans as a dashed span line per copy. Selecting it shows its parameters and the four member types in the properties palette; changing one regenerates the members in place, keeping their ids, marks and comments. A member you edit by hand (moved, retyped or deleted) is detached and is not regenerated; *Reset Members* in the palette makes the truss manage every member again. Deleting the truss deletes its members, and copying it makes a new truss with its own members.

*Light Steel Frame* (*Structure → Framing*, steel) and *Wood Frame* (timber) open a dialog that frames walls: the *System*, the stud *Spacing* (0.4 m for light steel, 0.6 m for wood), the types of the studs, of the tracks or plates and of the headers and sills (the system's catalog types by default), a *Double top plate* (wood only) and *Blocking* at mid-height. OK frames the selected walls, or every wall of the active level when none is selected; curved walls and walls already framed are left out. Studs stand at the ends of the wall and every spacing along it, with king and jack studs, a header, a sill under windows and cripples at each door and window. The studs, tracks, headers and sills are ordinary columns and beams, so they get tags, schedules, 3D views and IFC export; the framing itself draws nothing in plans. Selecting a framing shows its system, spacing, double top plate, blocking and the three member types in the properties palette; changing one regenerates the members in place, keeping their ids, marks and comments, and they follow the wall and its doors and windows when those move or change. A member you edit by hand (moved, retyped or deleted) is detached and is not regenerated; *Reset Members* in the palette makes the framing manage every member again. A member of a framing shows a *Framing* row in the palette whose *Select* button selects the framing. Deleting the wall deletes its framing and members.

*Structure → Connections* (steel and timber) places connections with default sizes on the selected columns (base plates) or beams, else on the active level's, at the ends that suit the kind: end plates and bolted joints where a beam stops at a column, fin plates at a column or a beam, hangers where a beam meets a beam. Ends that already have one are skipped, and the status bar reports how many were placed. Plates and bolts follow their member, go with it when it is deleted and are not copied with it. Selecting a connection shows its kind, the member and its end, the plate thickness, width and length (*auto*: from the section), the bolt diameter, rows, columns, spacing, edge distance and (base plates) anchor length, with the plate mass and bolt count; a connection whose end no longer suits it draws nothing and says so.

## Structural profiles

*Manage → Profiles* opens the Profile Manager: the project's structural profiles, which column and beam types are drawn and built with, grouped by material (steel, cold-formed steel, timber, concrete) under a search box.

- **New** makes a profile of a standard shape (I-section, channel, angle, cold-formed sections, tubes, rectangle, circle, concrete T and L, or a sketch) with its default dimensions and a name from its size; **Duplicate** copies the selected one; **Delete** removes it, and when column or beam types use it, the profile picked under the buttons takes its place in them in the same step.
- **Import from catalog** lists the built-in series (W and HP per ABNT NBR 15980:2024 and ASTM A6/A6M, IPE, HEA, HEB, the NBR 6355 cold-formed sections, sawn timber and glulam, square, rectangular and circular hollow sections); tick designations (the full names, e.g. `W150x13`, `W150x22,5 (H)` for the wide-flange column sizes), filter by text, and *Add* copies them in as profiles that remember their catalog entry.
- The selected profile's outline is drawn to fit, with its centroid, axes and overall depth (d) and width (bf). Its name, material and dimensions are edited in the table (millimeters; a dragged value is one undo step); a value the profile cannot take is shown in red and the previous one comes back. The section properties follow: area (cm²), mass per meter (kg/m), Ix, Iy and J (cm⁴), Wx and Wy (cm³), rx and ry (cm), and the types using it.
- Hovering a dimension's symbol (d, bf, tw, tf…) tells what it measures. In the catalog, a refused import is shown in red in the catalog itself, and a note asks to tick designations while none is ticked.
- **Edit sketch** (sketched profiles) opens the profile in a sketch in place of the views, around the axes x = 0 and y = 0: the outline and the openings inside it are drawn and changed with the usual sketch tools. *Finish* writes them to the profile (points that did not move keep their expressions, so they still follow the sketch's parameters) and every type using it follows; a sketch that does not close shows why and stays open. *Finish* and *Cancel* both go back to the manager. The sketch is part of the manager's session: the manager's Cancel also undoes what *Finish* wrote. It opens from the manager on its own, not over Type Properties.
- Every change is a `profile_*` command; OK keeps them and Cancel undoes them all.

In **Type Properties**, column and beam types have a *Profile* row in place of the old section fields: a list of the project's profiles grouped by material with a search box, and *Manage…*, which opens the Profile Manager on the type's profile. Below it, the profile's rotation (degrees) and *Mirrored* turn and flip it in the type, and a read-only row gives the profile's d × bf. A type with no profile shows "—" and keeps its own section until one is picked. Changes go through `type_set`, and OK/Cancel keep or undo them with the dialog's other changes.

## Cable trays and valves

*MEP → Electrical → Cable Tray* (`TY`) draws cable tray runs like conduits: click the ends of each run, one after the other; a new elevation while drawing adds a vertical run, and Backspace takes back the last segment. The options bar sets the circuit the trays carry and their elevation (by default 30 cm under the level above, or the height of the tray a run starts on). A project without a cable tray type gets one the first time (200 × 100 mm, ladder).

*MEP → Plumbing → Valve* (`VL`) places a valve on the pipe clicked, where it was clicked. A project without valve types gets one per kind the first time: gate, ball, check and globe valves.

- **Types**: a cable tray type sets the width, the height, the construction (ladder, solid bottom or perforated) and the material; a valve type sets its kind and material. A valve has its pipe's diameter.
- **Networks**: trays join other trays where their ends meet or an end lies on a run (elbows, tees and crosses, listed by `mep_fittings`), not conduits or pipes. A valve is a node of its pipe's network; it moves, is copied and is deleted with the pipe, and its properties set its distance from the pipe's start.

### Pipe Catalog

*Manage → Project → Pipe Catalog* (also *Load from catalog…* at the end of the pipe tool's type list) opens the Pipe Catalog: on the left, the project's pipe series and, under them, the built-in series not loaded yet (Brazil, Europe, US), filtered by region and by use (water or drainage). On the right, the selected series' standard, material, pressure class and use, its sizes (outside diameter, wall and inside diameter, in millimeters, or inches in imperial projects; a check mark where the project has a type of the size) and, folded, the fittings sold for it with their socket depths, laying lengths and body diameters. Check sizes and press *Create types* to make pipe types of them (a built-in series is loaded first); *Load series* loads one without types. *Import file…* reads a series file (JSON, as *Export…* writes it; a code the project has is renamed), and *Delete* removes a project series, its pipe types becoming free with the diameter they had. OK keeps the changes, Cancel undoes them all.

In **Type Properties**, a pipe type has a *Pipe series* section: the series (or *Free*), and *Load from catalog…*, which opens the Pipe Catalog over the properties; the size, picked from the series' rows; and the row's outside diameter, wall, inside diameter, pressure class and standard, read-only. A free type keeps its diameter and gets an inside diameter of its own, used by sizing. The pipe tool's type list groups the types under their series, from the smallest size up, with the free types last and *Load from catalog…* at the end.

Where pipes of one series meet, the fitting is matched to the series' catalog (see `mep_fittings` in the automation guide): after a pipe is drawn, the status bar names the fittings it made ("Fittings: Elbow 90° PVC soldável 25 mm") or warns of one the series does not sell, with the reason. The fittings table of *Systems* lists catalog fittings by name; a missing one is marked ⚠ in red, with the reason in its tooltip, and a composite one lists its pieces in its tooltip.
- **Views**: electrical plans draw trays as wide as they are, lightly tinted in their circuit's color, with the rungs of ladder trays and a tag with the section and circuits; plumbing plans draw valves with the usual symbol (two triangles meeting at their tips; a hollow circle for ball valves, a filled one for globe valves, a filled triangle for check valves). 3D views, sections and elevations show trays as open channels and valves with their body and handwheel or lever. Schedules list a tray's width, height and length and a valve's diameter and system.
- **IFC**: trays are written as `IfcCableCarrierSegment` (`CABLETRAYSEGMENT`), their fittings as `IfcCableCarrierFitting`, valves as `IfcValve` (`ISOLATING` for gate and ball valves, `CHECK`, `REGULATING` for globe valves) in their pipe's system. Imported back, they come in as components keeping their IFC class.
- From the command line or MCP: `cable_tray_create`, `cable_tray_type_create`, `valve_place` (with `point` or `distance`, and `kind` or `type`) and `valve_type_create`.

## Lightning protection

The *MEP → Lightning Protection* group draws a lightning protection system. Its elements belong to a lightning protection system, made with the first of them, and show in the level's lightning protection plan (*MEP → Documentation → Lightning Protection Plan*), which the tools open when another view is active.

- **Conductor** (`LC`) draws conductors like conduits: click the ends of each one. Over a roof a conductor lies on its surface, so a roof conductor follows the roof under its ends; a new elevation while drawing adds a down conductor at the last point. A vertical run is a down conductor, a run below the level is earthing, the others roof conductors; the role can be changed in the properties. A project without a conductor type gets one the first time (8 mm, copper); a conductor type sets the diameter and the material.
- **Air Terminal** (`AT`) places an air terminal (a lightning rod) on the roof under the point clicked; its height is a parameter of each terminal (1 m by default). **Earth Electrode** places a driven rod (2.4 m by default) with its top 50 cm below the level. **Earth Ring** lays buried conductors around the walls of the level, 1 m out from their outer faces and 50 cm deep.
- **Check** shows how the air termination covers the roofs for a protection class (I to IV): the exposed upper faces of roofs are sampled about 1 m apart, and each point is protected when one air terminal or roof conductor protects it by itself, by the rolling sphere method (radius 20, 30, 45 or 60 m) over the plane of the roof's eaves or, on flat parts, within half the mesh width (5, 10, 15 or 20 m) of a roof conductor. Protection between terminals and by the building itself is left out, so the result errs on the safe side; check the design with the applicable standards.
- **Views**: the lightning protection plan draws roof conductors as lines in the system's color, buried ones dashed, down conductors as a filled circle with a stroke, air terminals as a ring around a dot and earth electrodes with the earthing sign; conductors meet in clamps. 3D views show conductors and rods. Schedules of lightning conductors list their role (*Function*), diameter, length and system; schedules of components count terminals and electrodes. *Systems* lists each lightning protection system with its terminals, electrodes and conductor lengths by role.
- **IFC**: conductors are written as `IfcCableSegment` (`CONDUCTORSEGMENT`), their clamps as `IfcCableFitting`, air terminals and earth electrodes as `IfcProtectiveDevice` of the user-defined types `AIRTERMINAL` and `EARTHELECTRODE` (IFC4 has no class of their own), in an `IfcDistributionSystem` of type `LIGHTNINGPROTECTION`.
- From the command line or MCP: `lps_conductor_create`, `lps_conductor_type_create`, `earth_ring_create`, `air_terminal_place`, `earth_electrode_place` and `lps_check`.

## Structured cabling

The *MEP → Communications* group places racks and data outlets. They show in the level's communications plan (*MEP → Documentation → Communications Plan*), with the cable trays and the conduits that carry the cabling.

- **Rack** places a wall rack (on a wall, like the electrical devices; Space turns it) and creates its cabling: a data system fed by the rack, coded after its mark (`R1`, `R2`…).
- **Data Outlet** (`DO`) places data and voice outlets cabled to the rack chosen in the options bar (by default the project's only rack). A data outlet type sets its jacks (two by default); each jack takes a cable back to the rack. The properties show the outlet's jacks and the estimated length of its cables.
- **Cabling** lists each rack's outlets and cables, their total and longest length, and the cables over 90 m (the limit of a permanent link). Lengths are estimated along the usual route: up to the ceiling of the outlet's level, across along the two axes, down to the rack, plus 3 m of slack.
- Cable trays and conduits carry the cabling like circuits: their properties and *Systems* list both. Schedules of components can show each outlet's *Cable length* and *System* (its rack's cabling), and count the outlets per rack.
- **IFC**: data outlets are written as `IfcOutlet` (`DATAOUTLET`) and racks as `IfcCommunicationsAppliance` of the user-defined type `RACK`, in an `IfcDistributionSystem` of type `DATA`.
- From the command line or MCP: `rack_place`, `data_outlet_place` (with `rack` or `system`, and `ports`), `cabling_list`, and `device_type_create` for any built-in device type.

## Drafting views

- **View → Drafting View** (also the **+** of *Drafting Views* in the project browser) creates a 2D view that is independent of the model: it shows no walls, floors or other model elements, only what is drawn in it — text notes, dimensions and imported CAD drawings or images. It is meant for standard details and other drawings that are not cut from the model.
- It has its own **scale** (1:10 by default; 1:1, 1:2 and 1:5 are in the list too) and **detail level**, set in its properties, and its own *Visibility/Graphics* for the annotation and imported drawing categories (it has no template, phase or visual style, since it does not show the model).
- The *Text*, *Dimension*, *Import CAD* and *Import Image* tools work in it as in other 2D views; dimensions in it measure only what they are drawn on.
- Drag it from the browser onto a sheet like any other view, and export it with *Export Image*, *Export PDF*, *Export SVG* or *Export DXF*. Deleting it deletes what was drawn in it.

## Callouts and detail views

- **View → Callout** draws a callout in the active floor plan, ceiling plan, section or elevation (greyed out in other views, saying why): click two opposite corners of the region to detail. It makes a detail view of that region at a larger scale, listed in the project browser under the parent's kind (*Floor Plans*, *Sections*…), that stays live with the model and is cropped to the rectangle; draw detail lines, regions, detail components, texts and dimensions in it as in any view. The options bar picks the scale (*Automatic*: about five times larger than the parent's) or, under *Shows*, an existing drafting view the callout points to instead of a new detail view.
- The parent draws the callout as a rectangle with rounded corners and a tag with the detail's number over the sheet's number once the detail is placed on a sheet. With the Select tool, click the callout to select it (its view's properties show, with *Open View* and *Remove Callout*), drag it to move it or drag a corner to resize it — the detail view's crop follows — and double-click it to open its view. *Delete* deletes the detail view, which removes the callout.

## Interior elevations

- **View → Interior Elevation** (in a floor plan) places a marker where you click in a space closed by walls, with or without a room, and makes its views. The options bar picks *Four directions* (four views: each looks from the marker at the wall on its side) or *One per wall* (a view per wall of the space: each looks square on at its wall). With rooms selected, **Interior Elevations** (their *Modify | Rooms* tab and the right-click menu) does the same at each room's point. The views are listed under *Elevations*, named after the room and numbered clockwise from north (*Kitchen 1*, *Kitchen 2*…), at 1:50.
- Each view fits the space: across, between the side walls' inner faces; up, from the floor to the ceiling over the marker, else to the floor or roof above, else to the room's height or the level above; in depth, up to the far wall's outer face, so its doors, windows and what is fixed to it show. The views follow the walls, the marker and the room as they change; while no walls close the space around the marker a view is empty.
- In plans the marker is a circle with a filled arrow and number per view (the drawing number once the view is on a sheet). Double-click an arrow to open its view. Selected, the marker's properties have a checkbox per side (*North*, *East*, *South*, *West*: unchecking deletes that view, checking makes it again with the lowest free number; the last side stays), *Open* for each view, its *Rotation* (the four sides turn together, to face slanted walls) and its room. Drag it to move it; deleting it deletes its views.
- *One per wall*: each view is cut a *Distance from wall* in front of its wall (1 m by default, and never behind the marker), shows that wall's stretch of the space and is numbered clockwise from north as seen from the marker. Walls with less than the *Minimum length* along the space (0.30 m by default: column faces, short returns) get no view. The marker draws each arrow in front of the middle of its wall; its properties list the walls clockwise from north (*Wall A*, *Wall B*…) with a checkbox each, and *Faces* switches between the two modes, remaking the views. Each wall is seen on the face that bounds the space. Deleting a wall deletes its view; a wall that only stops bounding the space keeps its view, listed as *Wall out of the space*, which says so instead of a drawing until the wall bounds the space again or its box is unchecked.
- An interior elevation's properties have *Automatic extents*: off, the view keeps the crop it has, which can then be edited like a section's. With it on, the view draws the floor and the ceiling of its space as cut lines across what it shows. View templates apply to interior elevations as to the other elevations (scale, detail level, visual style, category graphics, filters).

## Detail lines

- **Annotate → Detail Line** (`DL`) draws 2D lines that belong to the active view only: a floor plan, ceiling plan, elevation, section, legend or drafting view (the button is greyed out in other views, and says why). They are drawn on top of the model and show nowhere else.
- The tool opens the **Modify | Place Detail Line** tab (Esc or another tool goes back to the tab shown before). Its highlighted *Draw* group picks the shape — *Line*, *Rectangle*, *Inscribed* and *Circumscribed Polygon*, *Circle*, *Ellipse*, *Arc by 3 Points*, *Arc by Center*, *Tangent Arc* (from the free end of a detail line) and *Spline* (Enter, Esc or a click on the last point ends it), and *Fillet Arc*, which picks two straight detail lines and rounds their corner with an arc of the options bar's *Radius* — and its *Line style* group the **line style**: *Thin*, *Medium*, *Wide*, *Hidden*, *Dashed*, *Center*, *Dotted* or one of the project's (its launcher opens *Line Styles*). The options bar has *Chain* for lines and tangent arcs (on: each goes on from the last end until the chain closes or Esc), *Sides* for polygons, *Offset* for rectangles, polygons, circles and the arcs by 3 points or by center (the lines lie that far from the shape: outside a closed one, to the left of an arc; negative the other way), a *Radius* that rounds the corners of rectangles and polygons and with which a circle takes one click, and what to click next. `detail_line_create` takes `offset` and `radius`, and `detail_line_fillet` rounds a corner, from the command line. Points snap to the model, imported drawings and other detail lines (ends, middles, centers, quadrants), to where two lines or arcs cross, and, once a curve has its first point, to the foot of the perpendicular from it and to the points where a line from it touches an arc or circle; these snaps work in the other drawing tools too (walls, sketches, grids). After the first point, type a line's length (Tab switches to its angle), a circle's or arc's radius or a rectangle's width and depth, and press Enter; Esc drops the typed value first. Each curve becomes an element as soon as it is drawn (one per segment of a chain or side of a rectangle or polygon); Esc drops the curve in progress, a second Esc leaves the tool.
- Selected, a detail line shows its style, view, shape, length and radius in the properties palette, where the style can be changed, and grips at its ends, an arc's middle, a circle's or ellipse's center and on their outline to reshape it. *Move*, *Copy*, *Rotate*, *Mirror*, *Array* and *Delete* work on it, in drafting views, elevations and sections too (there they take only what the view owns: detail lines, texts and dimensions); *Trim/Extend to Corner*, *Trim/Extend*, *Split* and *Offset* work on its curve (two detail lines meet at a corner; a detail line also trims to a wall, beam or grid; circles split into halves; arcs and circles offset concentric).
- *Visibility/Graphics* hides or overrides them with the *Detail line* category. They print on sheets, export with the view (DXF puts them on a layer named after their style) and are left out of 3D views and IFC.

## Line styles, filled and masking regions

- **Manage → Standards → Line Styles** (also the launcher of Annotate's *Detail* group) opens a dialog with the built-in line styles (read only) and the project's own: their name, weight, color and dash pattern are edited in place, and the table says how many elements use each. *New* adds a style; *Delete* removes the selected one, and what used it moves to the *Thin* style. OK keeps the changes, Cancel undoes them all. The line-style lists of the Detail Line tool, of a selected detail line and of a region's boundary show the project's styles after the built-in ones.
- **Annotate → Filled Region** (`FR`) and **Masking Region** open the sketch mode in the active floor plan, ceiling plan, elevation, section, legend or drafting view (greyed out in other views, saying why): draw the boundary with the sketch tools — loops inside the outline become openings — and click *Finish*. A filled region is filled as its type says (pick the type in the options bar's type list; the first region makes a type with diagonal lines over white) and edged in the thin style; a masking region is opaque white with no boundary and hides the model's lines under it. Both are drawn over the model and under the view's annotations (detail lines, dimensions, texts, tags, grids), in that view only.
- Selected, a region shows its boundary style (any line style, or *None*), view, area, perimeter and number of openings in the properties palette, and its type in the type list. **Edit Boundary** (Modify tab) reopens its sketch in its own view. *Move*, *Copy*, *Rotate*, *Mirror* and *Delete* work on it, outside plans too. **Edit Type** shows a filled region type's *Fill*: a foreground and a background pattern, each with its color (a *Solid* pattern fills with its color; a *None* background lets the model show between the pattern lines).
- *Visibility/Graphics* hides or overrides them with the *Filled Region* and *Masking Region* categories. They print on sheets and export with the view (DXF puts their fills as solids and their pattern lines on a layer named after the boundary's style) and are left out of 3D views and IFC.

## Tags, grid bubbles and view marks

- **Manage → Standards → Tag Types** (also the launcher of Annotate's *Tags* group) lists, for each target (doors, windows, rooms, columns, beams, footings and pile caps), its tag types, and the view mark types of sections and elevations. New projects have one type of each, drawn as plans always drew; a target with no type (in an older file) shows its *Built-in default*, which draws the same. *New* makes a type of the selected row's target, *Duplicate* copies the selected type and *Edit…* opens it in Type Properties — on a built-in default it first makes the type. OK keeps what the dialog made, Cancel undoes it.
- **Type Properties** of a tag type edits its text *lines* (each a text with `{Field}` placeholders — the *Field* menu inserts the target's schedule fields and `{Mark}`, `{TypeName}`, `{Section}` — and its size; *Add line*, the arrows and ✕ add, reorder and remove them), the text color and an opaque background, the *Symbol* (shapes, or any detail component of the project, drawn at paper size with its texts' fields filled in), its width and height (0 fits the text plus the padding), the line weight and color, the leader (*When moved*, *Always*, *Never*) and its end, and the orientation (*Horizontal* or *Along the host*). A text type edits its text size on paper and the end new leaders get; for titles of 5, 7 or 10 mm, *Duplicate* the 2.5 mm or 3.5 mm type and give the copy its size. A grid type edits which ends get a bubble, the bubble's symbol and size, the name's size, the line weight, color and pattern. A view mark type edits the head (diameter, symbol, the line across it, color), the top, bottom and label texts (`{Number}`, `{Sheet}`, `{Name}`, `{Letter}`), the arrow and its color, and for sections which ends get a head and the line weight.
- Selected in a plan, a door, window, room, column, beam, footing or pile cap shows a **Tag** section in the properties palette: the tag type of this element in this view (or *From the view*), its own rotation, its leader, *Hidden* and *Reset Tag*. A selected grid shows which ends get a bubble (or *As the type says*), *Hide bubbles in this view* and *Reset Tag*, in plans, elevations and sections. A plan's own properties pick the tag type of each target (*Automatic*: the project's first), a section's or elevation's its *Mark type*.
- In the view, with the Select tool, a tag is dragged to a new spot (a click on it still selects its element, a room's too), the element selected alone shows a round grip past its tag's right side that turns it (whole degrees; Shift: steps of 15°), a grid's bubbles are dragged off the line with an elbow leader (plans, elevations and sections), and an elevation's marker is dragged in a floor plan. A right click on a tag or a bubble offers *Hide Tag* and *Reset Tag*. Every change is one undo step, through `tag_set` and `mark_move`.
- In services plans the tags of pipes, conduits and cable trays (system, diameter, slope) are tags like these, with their own tag types (*Tag Types*: Pipes, Conduits, Cable trays). The plan's *Label fittings* property labels each fitting with its catalog piece (a fitting the series does not sell in red, circled, with why); a label is dragged, hidden and reset the same way (`fitting_tag_set`).
- In elevations and sections each level is a line across the view with a head (a triangle, its name and its elevation) at the right end. With the Select tool a head is dragged up or down off its line with an elbow, so the heads of levels close together do not overlap (dropped a few points from the line, it goes back onto it). A right click on a level's line or head offers *Hide Level in View* (for plotting: other views still show it), where its heads go (*At the end*, *At the start*, *At both ends*, *None*) and *Reset Level in View*. The category *Levels* in *Visibility/Graphics* hides all of them or gives them a line color, weight, pattern or halftone, and the dialog lists how many levels the view hides with *Show Levels*. Every change is one undo step, through `level_head_set`.
- A tag's text color, a grid type's color and a view mark type's color color their texts on screen and in every export (PDF, SVG, PNG; DXF writes the nearest color index).

## Fill patterns

- **Manage → Fill Patterns** (also *Fill Patterns…* in the material browser's Graphics tab and in a filled region type's *Fill*) lists the built-in patterns (read only) and the project's own, each with a drawn swatch. A project pattern has a name, a description, a kind — *Drafting* (lengths in millimeters on paper: the same printed size at any view scale) or *Model* (real millimeters: tiles and brick courses that scale with the view) — a scale, and line families edited in a table: angle, origin, *Shift* (how far the dashes move along from one line to the next), *Spacing* (the distance between lines) and *Dashes* (millimeters, comma-separated: positive drawn, negative gaps, 0 dots). In an imperial project a drafting pattern's lengths read and are typed in inches; model patterns stay in millimeters. The preview under the table follows every change.
- *Import .pat…* reads a `.pat` hatch pattern file (the plain-text format CAD programs share) and opens a list of its patterns with their swatches: tick the ones to bring in, choose their kind (or as the file's `;%TYPE=MODEL` markers say), the file's units (or its `;%UNITS=` marker, else millimeters), a scale, and what to do with names the project already has (add a number, replace, skip). Patterns with a problem are left out and listed with their line. *New*, *Duplicate* and *Delete* complete the list; a pattern in use is deleted only with the pattern chosen to take its place. OK keeps the changes, Cancel undoes them all.
- The pattern pickers of the material browser (surface and cut patterns), of filled region types and of *Visibility/Graphics* overrides list the project's patterns after the built-in ones. Plans, sections, elevations (textures style), legends, filled regions and detail components hatch with them, clipped to the fill, and every export (PDF, SVG, PNG, DXF) gets their lines. Patterns denser than 0.1 mm on paper are left out at that scale (they would print as a gray blot). 3D views show custom patterns as the material's plain color.

## Material libraries

*Libraries…* in the material browser (*Manage → Standards → Materials*) opens the **Material Libraries**: materials of one region or standard that a project picks and imports, as the Pipe Catalog does with pipe series. The built-in libraries are Brazil's *Structural steels* (NBR 7007, NBR 7008 and ASTM grades, with their yield and ultimate strengths), *Reinforcing steels* (CA-25, CA-50 and CA-60, NBR 7480) and *Concretes* (C20 to C90, NBR 8953, with the secant modulus of NBR 6118), and international libraries of materials by their physical kind, with no brand or trade names: *Paints and varnishes* (by gloss), *Ceramics* (tiles by the water absorption groups of ISO 13006, roof tiles), *Natural stones*, *Mortars, plasters and boards*, *Woods and panels* and *Glass*, with color, gloss (matte, satin, glossy, polished), density, thermal conductivity and specific heat (ISO 10456); Brazil's region adds the same kinds with the values of NBR 15220-2, Brazilian wood species and stones, and thermal insulation; other regions can be added the same way. Pick a region (it shows its own libraries and the international ones) and a library on the left; the right lists its materials with their color and the values the library has: density, thermal conductivity (λ) and specific heat (c), modulus of elasticity and the strengths their standards give (*fck* for concretes, *fy* and *fu* for steels), marks those the project has, and folds the documents the values come from under *Sources*. Check materials and press *Load selected*, or *Load all*; a material whose name the project has (in any language) is kept as it is. Materials are named in the language of the interface. *Import File…* reads a library file (JSON) and *Export Materials…* writes the project's materials as one, for another project or another user. OK keeps what was loaded, Cancel takes it out again. The materials keep the market's names (*Aço MR250 (NBR 7007)*, *Concreto C30 (NBR 6118)*); a material's physical properties now include its *Yield strength*. Commands: `material_catalog`, `material_library_import`, `material_library_export`.

## Detail components

- **Annotate → Detail Component** (`DC`) places a detail component — a reusable 2D component for construction details — in the active floor plan, ceiling plan, elevation, section, legend or drafting view (greyed out in other views, or when the project has none, saying why). The options bar's type list picks the component, and rotation (with a *Turn 90°* button), scale and *Mirrored* set how it lands; it follows the cursor, snapping like the other tools, and a click places it. It is drawn over the model and its regions, under detail lines and annotations, in that view only.
- **Insert → Library → Create Detail Component** turns the selected detail lines, regions, texts and detail components of the active view into a new detail component type (named *Detail 1*, *Detail 2*…; rename it in its type properties), placed where they were, in one undo step. A detail component may hold others (nested), never itself.
- Selected, a placed detail component shows its component and view, and its rotation, scale and *Mirrored* in the properties palette. *Move*, *Copy*, *Rotate*, *Mirror* and *Delete* work on it, outside plans too. Its pieces are edited with the `component_sheet_piece_*` commands from the command palette (the component editor is for 3D components).
- **Insert → Component Library** lists detail components with the others (their kind is *2D detail*) and loads them, with the components they nest. With *Blocks as components* on (**Preferences → General → Import**), **Insert → Import CAD…** brings a DWG or DXF file's blocks in as detail components placed where the file inserts them, instead of exploding them into the imported drawing.
- The Component Library has two sources, picked at the top of the window: *My Folders*, the folders of **Preferences → File locations**, and **3D CraftHouse**, the open library of parametric components published at [3dcrafthouse.constructcraft.net](https://3dcrafthouse.constructcraft.net) (CC BY 4.0). The window is a browser in three columns: on the left the filters (each kind of component the source has, with how many, then its folders or its authors when there are several) with the source's buttons under them; in the middle the components as cards, with the count over them, a search field and the order (by name or by kind) at the top; on the right the details of the component picked (its 3D picture, plan, types, parameters and connectors). A click picks a card and a double click loads it. Picking *3D CraftHouse* reads its catalog from the site, and the same search and filters apply. Each card has a small 3D picture of its first type (a door or a window shows in a piece of wall). A folder's pictures are rendered by the app the first time a component is shown and kept in its data folder; 3D CraftHouse publishes the pictures of its components, downloaded as the cards show them. An online component is downloaded only when it is picked (its plan shows once it has arrived); a card whose picture the library does not publish shows a placeholder, or the app's own picture once the component has been downloaded. Pictures and components are kept in the app's data folder, so the next time they are there at once; *Refresh* downloads them again. *Load into Project* brings the component picked into the project with its types, as from a folder. *Open Site* shows the library in the browser, where each component has a 3D preview that can be turned. Nothing is downloaded until that source is picked, and without a connection the window says why the catalog or the component could not be read. A plugin with network access can add its own catalogs as more sources, each with its categories, a *Color* filter and a *Max size* (width, depth and height) filter, its pictures, and *Open Website* for an item's page; *Load into Project* downloads the item into the plugin's cache, checks it and loads it as a component.
- *Visibility/Graphics* hides or overrides them with the *Detail component* category. They print on sheets and export with the view (DXF writes them as blocks and inserts) and are left out of 3D views and IFC.

## Imported CAD drawings

- **Insert → Import CAD…** places a DWG or DXF drawing in the active floor plan, ceiling plan, elevation, section, legend or drafting view (the button is greyed out in other views, and says why). You can also drop `.dwg` and `.dxf` files on the window. The file dialog starts in the *Projects folder*. The drawing keeps its origin at the view's origin, unless that leaves it more than 1 km from the model (a drawing in survey coordinates), then it is centered on what the view shows. The status bar says how many items and layers were read, how many entities were not drawn (3D solids, images, infinite lines…) and which units were assumed when the file has none.
- **Insert → Import Image…** places a picture (PNG, JPEG, GIF, BMP, WebP) or an SVG drawing in the active view, the same views as *Import CAD*, centered on what the view shows; dropping such a file on the window does the same. A picture is as large on paper as its resolution makes it (96 dpi when the file declares none): set *Scale* in its properties (100 for a plan scanned at 1:100) or `width` in `image_import`. An SVG keeps its paths, fills and embedded pictures in their own colors (its texts are not read). It is an imported drawing like a DWG: pinned, moved, turned and hidden the same ways, printed and exported with the view.
- **File → Export DXF…** writes the active view (any view; a schedule as its table) as a DXF drawing for other CAD programs, as printed: plans, elevations and sections at full size in millimeters (texts at their printed height times the view's scale), a sheet in paper millimeters. Each element goes to the layer of its category (`WALL`, `DOOR`…; annotations to `ANNOTATION` and `TEXT`), dashed and dash-dot lines get line types, opaque fills become solids, and colors are the nearest color index, so a plot style by color can give the pens their weights. The file is DXF R12, which every CAD program opens; it reads back with *Import CAD*.
- The drawing is a background to trace over: thin grey lines under the model, with its texts. It shows only in the view it was imported into (not in other plans or in 3D views), prints on sheets and exports, and is left out of IFC export. *Visibility/Graphics* hides or overrides it with the *Imported CAD* category.
- It starts **pinned**, so it is not moved by accident; *Unpin* it to move or rotate it with the usual tools. Clicking its lines selects it only where no model element is under the pointer.
- Its properties set the **units** (read from the file, else assumed), an extra **scale**, the **rotation**, the **position** of its origin, the **colors** (*Grey*, *Layer colors* with very light colors darkened for white paper, or *Black*) and **Halftone**. The *Layers* section shows or hides each layer (*All layers* toggles them all); layers that are off or frozen in the file start hidden.
- The drawing tools snap to its endpoints and vertices, midpoints, arc and circle centers (a circle marker), and to points on its lines.
- **Doors and windows** line up with it in plans, even where a wall covers its lines: the center of the opening, or either of its edges, snaps to a line of the drawing (or of the plan's underlay) that crosses the wall, such as a window's axis or a jamb, and to points within reach, such as the end of an axis drawn outside the wall; a square marks the point and a dashed line the part of the opening on it. The opening keeps to the wall while the pointer is a little off it. While placing, temporary dimensions run from the opening's center to both ends of the wall; type a distance to place the center that far from the wall's start, or press Tab and type it from the wall's end, then press Enter (or click). Backspace edits the value and Esc drops it. The window and niche tools have a *Sill Height* field in the options bar: it shows the type's sill, and a value typed or dragged there is the sill of the windows or niches placed next, until another type or tool is picked (doors have none).
- **Modify → Explode** (also the *Explode* button in its properties) turns the selected imported drawing into native elements of its view, in one undo step: its lines, polylines, arcs and circles become detail lines (one per segment; ellipses and splines come out as their segments), its fills filled regions of a solid type of their color, its texts text notes of a type of their size on paper. Each layer becomes a line style of its name and color (*Manage → Standards → Line Styles*), reused when one of that name exists; hidden layers are left out, and the result lands where the drawing was (units, scale, rotation, mirror). Pictures stay as an imported drawing; the color mode and halftone are not carried over. What it made is selected. A drawing that would make more than 100,000 elements is refused: hide layers first.

## Construction phases

- **Manage → Project Browser → Browser Organization** (also *Browser Organization…* in the menu of a group in the project browser) sets how the browser groups the views. *Default* lists them by view type alone, as before. *New* adds a named scheme that groups by view type and then by level, so each plan type holds a group per level with that level's plans; the lists under the schemes change what it groups by, from the outermost group in: *View type*, *Level*, *Discipline* (architecture, structure and each building service, for plans) and *Phase*. A view without a value for a criterion (a section has no level) stays beside that criterion's groups. The marked scheme is the one in use and the browser follows it at once; its name is edited in place and *Delete* removes it. Groups fold and unfold with a click and show how many views they hold; plans come in the order of their levels. The schemes are kept in the project. OK keeps the changes, Cancel undoes them.
- **Manage → Levels** lists the levels from the highest down, each with its name, its *Elevation* and the *Height to Next Level*. A new height moves every level above by the difference, so the other storeys keep their heights; an elevation moves that level alone and stays between the level below and the level above, so no value typed changes the order of the levels. Both are taken when the field is left. The mark at the start of a row (or a click in one of its fields) picks the level: *Add Above* and *Add Below* add a storey next to it, of the height of the storey beside it, with its floor and ceiling plans, pushing the levels beyond it away; *Delete* removes it with its plans when no element is on it. OK keeps the changes, Cancel undoes them. `level_set` (`height`) and `level_create` (`above` or `below`, `height`) do the same from the command line.
- **Manage → Phases** has three tabs. *Phases* lists the project's phases from earliest to latest with their name, description and how many elements are built and demolished in each; *Add* appends one, *Insert Before* puts one before the selected phase, ↑ ↓ reorder (a move that would put a demolition before its construction is refused), and deleting a phase moves its elements and views into the phase chosen under *Merge elements and views into*. *Phase Filters* sets, for each filter, how existing, demolished, new and temporary elements show: *Not Displayed*, *By Category* or *Overridden*. *Phase Graphics* sets the overrides used for each status (the same cells as Visibility/Graphics). OK keeps the changes, Cancel undoes them.
- The view's properties (plans, elevations, sections, 3D views, schedules) have a *Phasing* section with its *Phase* and *Phase Filter*; the filter is read-only when the view's template controls it. Elements show *Phase Created* and *Phase Demolished*. New elements are built in the active view's phase.
- **Modify → Demolish** (DE) demolishes the clicked elements in the active plan's, elevation's or section's phase; their doors and windows go with them.

## Design options

- **Manage → Design Options** lists the project's option sets. Each set holds alternatives for part of the model (say, two kitchen layouts); views show the main model plus one option of each set. *New Option Set* adds a set with two options; in each set the name fields rename it and its options, *Add Option* adds one, the *Primary* button picks the option views and IFC export show by default, × deletes an option with its elements (not the primary), *Merge Primary into Model* moves the primary option's elements into the main model and deletes the set with the other options and their elements, and *Delete Set* deletes the set with all its elements. OK keeps the changes, Cancel undoes them.
- **Manage → Active Option** (the menu next to it, labelled with the option being edited) picks *Main Model* or an option: new elements go into it, and views that show its set automatically show it while it is being edited. It is not saved with the project.
- The view's properties (plans, elevations, sections, 3D views, schedules) have a *Design Options* section with a row per set: *Automatic (primary option)* or a given option; it is read-only when the view's template controls it (the template manager has a *Design Options* row, off by default). An element's properties show its *Design Option* (main model or an option); doors, windows and other hosted elements show their host's, read-only. Elements of options a view does not show are left out of it entirely: they are not drawn, scheduled, joined with other walls or used to bound rooms.

## Sheets and title blocks

A sheet's properties set its **number**, its **title block** (a title block type of the project, or *None* for blank paper), its **paper size** (A0 to A4, ANSI A to ANSI E, ARCH A to ARCH E1 and ARCH E, the project's own listed first; or *Custom* with a width × height between 50 and 5000 mm, in inches in imperial projects) with *Portrait* to put the long side up, and its **issue date** (typed as `YYYY-MM-DD`; *Today* fills it in). *Sheet Fields* lists the title block's per-sheet fields: type a value for this sheet, or leave the row empty to use the title block's own text, shown greyed. When a piece of the active sheet's title block cannot be drawn (an expression that does not resolve), the status bar names it.

**Schedules go on sheets** like any view: drag one from the project browser onto an open sheet, or right-click it in the browser and choose *Place on active sheet* (`sheet_place_view`); a view is on one sheet at most, and for one already on another sheet the menu offers *Move to active sheet* instead (its tooltip names the sheet it is on). It is drawn as a ruled table at its printed size, with its name in the first row, its headers, a row per element its phase shows and the totals; it follows the model, and the sheet's PDF, SVG, PNG and DXF carry it. *Export Image*, *Export DXF* and `view_export` also write a schedule alone as its table.

**Manage → Project → Project Information** has a *Project fields* table: your own values, such as the engineer or the permit number, each with a name and a value. *+ Add field* adds one, a name is changed by typing over it (Enter), × removes it. Title blocks show them as `{project:Name}`.

**Massing & Site → Site → Site Location** places the project on an OpenStreetMap map. Search an address, place or coordinates (Enter or *Search*; pick one of several results), or drag the map: the red marker in the middle is the project origin, the arrow is project north and the red square is the area of map data to bring in, turned with *True north*. *Elevation → Get* reads the height above sea level from an open elevation model (accurate to meters; type a surveyed value over it), and *Address of this point* fills the address of the marker. OK stores the latitude, longitude, elevation, true north and address (the project address is rewritten from the parts, for title blocks and IFC). *Import Surroundings* downloads the map data of the square into the chosen floor plan: a pinned drawing with layers for buildings, streets, paths, railways, water, green areas, trees and street names, and, with *Buildings as masses*, a context mass per building (the map's height or storeys, else two storeys of 3 m). Cancel undoes all of it. Map data © OpenStreetMap contributors (ODbL); the map, search and elevation need an internet connection.
A title block draws the whole sheet: border, margins, the block itself, logos. It is a component (category *Title Blocks*), so it is saved to and loaded from `.ccomp` files and the component library. **Modify → Title Block → Edit Title Block** (shown while a sheet is the active view; or *Edit Title Block* in a sheet's right-click menu, in the view or the project browser) opens the active sheet's title block in the editor; **Insert → Library → New Title Block** makes one from the standard layout and opens it; loading a title block from the library opens it too.

- **The Sheet view:** the editor shows the paper at a preview size: the sheet it opened from, or any named paper in portrait or landscape (*Preview on*, in the options bar). Its four edges are locked reference planes. The wheel zooms, a middle or right drag pans, a middle double-click fits the sheet.
- **Lines:** opens a sketch with the drawing and modify tools of [Sketching outlines](#sketching-outlines). *Finish* makes a stroke of each chain of curves, closed when its ends meet. A point on an edge is written `SheetWidth`, `SheetHeight` or `0`, and a point on a reference plane as the plane's name, so the stroke follows the paper: a line drawn on the right edge of an A3 stays on the right edge of an A1. Other points are kept to the hundredth of a millimeter. Lengths typed while drawing are lengths on the printed paper. A stroke's properties set its weight (millimeters), color and, when closed, its fill; *Edit Sketch* (or a double click) opens it again.
- **Text:** a click places a text. Its properties set the words, the height, the alignment (left, center or right on the baseline, or the middle of the block), the rotation and the position. *Insert field* adds a field at the cursor: sheet number, name, count and position, scale and paper; project name, number, client, address, author and project fields; today's date and the issue date; and the per-sheet fields. Fields show filled in from the sheet the editor opened from (or sample values); *Show field keys* shows them as typed, such as `{sheet_number}`. <code>&#123;&#123;</code> writes a brace.
- **Image:** pick a PNG, JPG or SVG file, then drag its rectangle; the picture keeps its proportions unless Shift is held. Drag it by its body to move it (its corner snaps to the edges and planes), or by its corner grips to move or size it. The picture is kept in the title block (and in its `.ccomp` file).
- **Reference Plane:** two clicks along a line make a plane square to the paper. Its position is an expression in millimeters that may read the paper (`SheetWidth - 10`).
- **Parameters:** numbers (in millimeters) and texts. *New per-sheet field* adds a text that each sheet may set in its *Sheet Fields*; the parameter's text is the default. *Sheet width* and *Sheet height* show the preview's paper.
- **Selecting:** click a piece, or drag a window around several; Delete removes them. A picked text or picture shows grips.
- *Finish* keeps the changes and *Cancel Editing* undoes everything done in the editor. Every sheet that uses the title block follows.

## Component modeling environment

*Edit Component* (*Modify | Components* with a component selected, the right-click menu, or *Edit Component…* in a component type's properties) opens a workspace of its own for the selected component, or the one the *Component* tool places. *New Component* (*Architecture → Model*) asks for a name and the kind of the component (furniture, casework, plumbing fixture, lighting, electrical, generic, door or window) and shows the parameters that kind starts with: width, depth and height for most, a diameter for lighting, the opening's width, height and sill for doors and windows; a generic component starts with none, and its parameters are yours to add. *Create* makes the component and opens it here; *Cancel Editing* removes it again, and *Finish* picks the tool that places it.

- **Views:** the project's views give way to the component's *Plan*, *Front*, *Side* and *3D* views. The wheel zooms, a middle or right drag pans, and a middle double-click fits the view. The options bar sets the views' scale (1:1 to 1:100), which sizes their texts and dimensions.
- **Ribbon:** the *Create* tab holds *Select*, *Extrusion*, *Revolution*, *Sweep*, *Blend*, *Reference Plane*, *Dimension*, *Equality (EQ)*, *Connector*, *Save Component…*, *Finish* and *Cancel Editing*.
- **Left panel:** the type whose values the views show, the parameters (name, value, whether elements may override it, ×, and *+ Parameter*) and the properties of the selected plane, dimension, piece or connector.
- **Reference planes:** three origin planes are always there: *CenterX* (center left/right), *CenterY* (center front/back) and *Base*. *Reference Plane* takes two clicks in the plan, front or side view; a mostly vertical or mostly horizontal line sets which way the plane faces. A plane's position is an expression (`Left + Width`), and its name can be used in any expression of the component, so a piece that reads `x = Left` follows the plane.
- **Dimensions:** *Dimension* takes two parallel planes, then measures them where you clicked. In its properties, a *Label* (a length parameter, or a new one typed under *New parameter*) makes the parameter drive the second plane. Changing the value changes the parameter, or moves the plane when the dimension has no label. *Locked* (or the padlock past the selected dimension's text) keeps the distance: the second plane is written as the first plus it, so it follows when the first moves, and a new value is kept the same way; a locked dimension shows a closed padlock. A labeled dimension is already held by its parameter, and a plane another expression sets cannot be locked over. Unlocking or deleting the dimension leaves the plane where it is.
- **Sketched pieces:** *Extrusion*, *Revolution*, *Sweep* and *Blend* open a sketch, the same as outlines in plans (see *Sketching outlines*): its ribbon (*Sketch: Extrusion*…) has the drawing tools (lines, rectangles, polygons, circles, ellipses and arcs), the Modify tools, *Finish* and *Cancel*; curves are picked, stretched by their grips and typed in the side panel. Draw in the plan, front or side view: the first curve fixes the view. Points snap to the sketch's own points and to reference planes, and a coordinate on a plane seen edge-on is locked to it, so the piece follows the plane; points on a circle or an ellipse whose center is on a plane are written from that plane. The options bar sets *Solid* or *Void*. *Finish* makes an extrusion at once; a revolution then asks for its axis, a plane seen as a vertical line or any point (Esc goes back to the outline). The new piece is selected: its properties set the name, *Void*, *Shown in plans*, the material and where it starts and ends (or its axis and angle), each an expression that the ⌖ menu locks to a plane. *Edit Sketch* in its properties opens its outline (a sweep's path, a blend's bottom then top) again; points that did not move keep the expressions they were written with.
- **Equalities (EQ):** *Equality (EQ)* takes three parallel planes in one view, in any order; the one between the others is kept halfway. Its position becomes `(a + b) / 2`, so it stays centered as the others move. When it cannot move (an origin plane such as *CenterX*, or a plane a labeled or locked dimension sets), the outer planes move instead: with a dimension between them (*Width*), the plane it measures from goes half of it from the middle, so the width stays centered; otherwise one outer plane mirrors the other. When none can move, the equality is refused; the view shows two dimensions marked EQ. Moving the middle plane by hand would break it and is refused; delete the equality first.
- **Connectors:** where pipes and conduits join the component (a fixture's water inlet and drain, an outlet's electrical connection). *Connector* places one with a click in the plan, front or side view; a coordinate near a reference plane seen edge-on is locked to it, so the connector follows the plane, and the depth starts at 0 (in plan it points down, elsewhere back). Every view, the 3D one too, shows connectors as rings in their system's color with an arrow the way runs leave (a dot when that is toward you, a cross when away). Their properties set the name, the kind of system, *X*, *Y* and *Z* (expressions the ⌖ menu locks to a plane), the direction and the diameter. A run drawn to a placed component joins it at its connectors (`component_connector_add`, `_set`, `_delete`).
- **Sketch points:** a sketched piece's properties list its points (and a sweep's path and section, a blend's top). Each coordinate is an expression; type a new one, or lock it to a plane seen edge-on in the sketch's view with ⌖.
- **Sweeps and blends:** a *Sweep*'s curves are an open path; a section is carried along it, set in the options bar as a rectangle (width × height) or a circle (diameter), centered on the path; corners are mitered. *Blend* takes a bottom outline, then (after *Finish*) a top outline drawn in the same view, and joins them; its start and end are set in its properties like an extrusion's.
- **Selection and keys:** click a plane's line, a dimension's line or text (highlighted under the pointer), a piece's edge or a connector to select it; Delete removes it, and Esc steps back through the tool's picks, the tool and the selection.
- **Script pieces:** `component_script_set` adds a script piece to a component, or changes its source (a `component_create` definition may hold one too); what it declares becomes the component's parameters (their names, kinds and instance flags come from the script; only their values change in the table). A script that does not load is reported above the piece. See [Scripted components](automation.md#scripted-components). In the properties palette, a placed scripted component shows *Instance Parameters* and *Type Parameters · shared* (checkboxes, text boxes, lists of choices and of materials) and any *Script Errors*; selected in a plan, its hotspots show as grips in their shape and color, and dragging one moves it.
- **Finish and Cancel:** every change applies to every type of the component and undoes like any other edit. *Finish* keeps them, *Cancel Editing* undoes everything done since the environment opened.

## Preferences

*File → Preferences* (Ctrl+,, also at the bottom of the home screen) holds the settings of the app itself; they are not part of any project and are kept between sessions. Pick a page in the sidebar on the left; each page starts with what it holds, and each setting has its name and what it does on the left and its control (a switch, a list or buttons) on the right. Changes show at once; **OK** keeps them and **Cancel** (or Esc) brings back the values the window opened with. **Restore defaults** (bottom left) resets the settings of the page shown; the language and the folders stay as they are.

- **General**: the interface language, *Check for updates automatically* (see the update notice below) and *Blocks as components* for imported drawings.
- **Interface**: the *Theme*, picked from three picture cards (light, dark, or the operating system's), the *Interface scale* (75–200%, everything grows: panels, icons, text; Ctrl+Plus and Ctrl+Minus change it too), the *Text size* (four sizes, shown as *Aa* from small to extra large; only the text, at any scale), *Start with the ribbon collapsed*, *Detailed tooltips* (when off, command tooltips show only the name, the shortcut and why a command is unavailable, without the description and the engine command) and *Reset panel layout*.
- **Drawing & navigation**: **Object snaps** choose where the drawing, Modify and measuring tools snap: *Snap to objects* turns object snaps on or off as a whole; *Every element in the view* makes them snap to everything the view draws (beams, footings, piles, components and the rest: the ends and corners of their lines, the middles of their sides and points on them), not only to walls, grids and outlines; and each kind of point has its own switch: endpoints and corners, midpoints, centers (columns, piles, pad footings, arcs and circles of imported drawings), intersections, perpendicular, tangent, the nearest point on a line, and the alignment guides. Free points still round to the zoom's increment. *Dragging in 3D views selects* (a left drag draws a selection box and Shift+drag orbits; off, the other way round) and *Trackpad scrolling pans the view*.
- **File locations**: the *Macros folder* (the macro file dialogs start there and *Manage → Run Macro* lists its macros), the *Projects folder* (where Open, Import IFC, Import CAD and the first Save of a new project start; a saved project is saved again next to itself), the component library folders (*Add Folder…*, *Remove*) and the *Plugins folder* (see [Plugins](#plugins); not set, a `plugins` folder in the app's data folder), *Plugin developer mode* and the *Development folder* (see *Developing plugins* under [Plugins](#plugins)). The component library window's *Manage Folders…* opens this page. A folder that no longer exists is marked *Not found* and skipped.
- **Saving**: the *Autosave* interval (off, or every 1, 2, 5, 10 or 15 minutes; see below) and how many recent projects the home screen lists.
- **Keyboard shortcuts**: every command with its keys. Click a command's box and type two letters to give it new keys (they replace the old ones at once, in tooltips, the palette and views); keys another command already has are refused and the row says which. Leave the box empty to take the keys away, and *Default* brings back the original ones. Search finds a command by name or keys. Ctrl shortcuts, Delete and Esc are fixed.

## Visual programming

*Manage → Macros → Visual Programming* opens the graph editor in a panel under the views, so the model and the graph are seen together (`constructcraft project.ccad --graph file.ccgraph` opens one at startup). A graph is a set of nodes joined by wires (see [Visual programming graphs](automation.md#visual-programming-graphs) for what the nodes do and how running again updates the model).

- **Adding nodes**: double-click or right-click the background to open the node search; type words of the node's name, group or description and press Enter (or click a match). Every engine command is a node, next to the built-in nodes (inputs, math, logic, lists, geometry, parameters, outputs) and the Lua node.
- **Wiring**: drag from an output (right side) to an input (left side), or the other way. Dragging from a wired input picks its wire up. Ports are colored by type; a wire between types that do not fit is refused with a message in the status bar.
- **Moving around**: drag a node to move it (with the others selected); drag the background to select with a box (Shift or Ctrl adds); the middle or right button pans; the wheel zooms about the pointer. *Zoom to Fit* frames the graph.
- **Inputs**: number, integer, slider, boolean and text nodes have their value on the node. The inspector on the right edits the selected node: its name (on input and output nodes, the name of the graph's input or result), the list lacing, the values of its unwired inputs (JSON, or plain text), a command node's *Show all inputs*, a Lua node's inputs, outputs and code, and *Use Selection* on *select_elements*. It shows the node's outputs, error or reason it was skipped after a run. With no node selected it shows the graph's name, *Allow file commands*, how many elements the graph made, *Select Elements* and *Release Elements*.
- **Running**: *Run* (F5) runs the graph through the engine as one undo step; the toolbar and the status bar show how many elements were created, changed and deleted. *Automatic* runs it after every change. Each node shows its value (or error) under it; clicking a node selects the elements it made.
- **Keys** while the pointer is over the panel: Delete removes the selected nodes, Ctrl+C / Ctrl+V copy and paste them, Ctrl+A selects all, Ctrl+Z / Ctrl+Y undo and redo graph edits (the model's own undo is on the quick access toolbar), Ctrl+S saves the graph.
- **Files**: *New*, *Open…*, *Save*, *Save As…* work with `.ccgraph` files (the dialogs start in the macros folder). Closing the panel, *New* or *Open…* with unsaved changes asks first.

## Macro editor

*Manage → Macros → Macro Editor* opens a panel under the views, in the graph editor's place (one of the two shows at a time, and each keeps its contents when the other opens), where a macro is written, checked and run a step at a time while the views above show each step's change. A macro is one `{"command": …, "args": {…}}` per line, with `//` comment lines (see [Macros in the app](automation.md#macros-in-the-app)).

- **Editor**: the text on the left, with line numbers. The command of each step is in color and `$step` and `$level` placeholders in the accent color. A check mark in the gutter marks the steps that ran, an arrow and a soft band the next one. A line with a problem is underlined (red for an error, amber for a warning) and has a dot in the gutter whose tooltip gives the message. A macro in the JSON array format runs too, without the per-line marks; *Format* turns it into one step per line.
- **Running**: *Step* (F10) runs the next step, *Step Back* (Shift+F10) undoes the last one, *Run to Cursor* (Ctrl+F10) runs the steps before the one at the text cursor's line, *Run to End* (F5) runs the rest and *Restart* (Ctrl+Shift+F5) steps back to the start. Each step is one undo step, as when a macro runs; with *Single undo step* on, *Run to End* makes the steps it runs one undo step. A step that fails leaves the position where it is and shows its error. Stepping back over a step is refused when the model was changed since (its message shows in the Result pane); *Restart* then asks whether to start over without undoing those steps. Stepping is unavailable while a macro is recording, a sketch, an editor, a dialog or a file operation is open, or when an error comes before the next step; the buttons' tooltips say why. Opening another project starts the run over and keeps the text.
- **Editing**: the macro is checked a moment after you stop typing, and with *Check*. *Format* rewrites the steps in the standard form, keeping comments and blank lines. *Insert Command…* opens the [command palette](#running-engine-commands) on the engine commands; its form's **Insert** adds the command with its arguments as a step after the cursor's line instead of running it. Steps after the position can be edited freely. When a step that already ran is edited, the run is marked as edited, and only *Restart* is available until it steps back to the start.
- **Result and Problems**: on the right, the last step's number, command and result (or error), and the problems found, as *line N: message*. Click a problem to go to its line.
- **Keys** while the pointer is over the panel or the text has focus: F10, Shift+F10, Ctrl+F10, F5 and Ctrl+Shift+F5 as above, and Ctrl+S saves the macro. While the text has focus, Ctrl+Z and Ctrl+Y undo and redo typing, not the model.
- **Files**: *New*, *Open…*, *Save* and *Save As…* work with `.ccmacro` files (the dialogs start in the macros folder). The toolbar shows the file name, with a dot when it has unsaved changes. *New* and *Open…* ask first when there are unsaved changes.

## Plugins

Plugins add commands to ConstructCraft (see [Plugins](automation.md#plugins) in the automation guide). *Manage → Plugins* holds two buttons: *Plugins…* opens the Plugins window, and *Plugin Commands* is a menu of the installed plugins' commands, by plugin, each named by its title. The [command palette](#running-engine-commands) also finds them by name.

**Plugins tab.** When a loaded plugin adds ribbon buttons (plugin API 2), the ribbon has a *Plugins* tab after *Manage*, with one group per plugin and panel, in the order the plugins load and then the order of their manifests. The buttons look and work like the built-in ones: large or small, with the plugin's icon drawn in the theme's colors (its own SVG, which may not reach any other file or image; the plugin icon when it has none or it cannot be drawn), and a tooltip with the label, what the command does, the plugin it comes from and, when it is unavailable, why. A button may need a selection (*Select at least one element*, *Select exactly one element*, *Select only elements of Walls*…) or a view of a kind (*Open a view of Floor Plans*…). A click opens the command's form. The tab goes away when no loaded plugin has buttons.

**Plugin exporters and importers.** A plugin may add file formats (plugin API 2): its exporters appear in the *File* tab's *Export* group, and its importers in the *Insert* tab's *Import* group, after the built-in buttons and a separator, each a plugin button with the export or import badge whose tooltip names the plugin. A click opens the save (export) or open (import) dialog for the format's extensions, then the command's form with the chosen file filled in, or runs the command at once when the file is all it asks for. Such a plugin needs no permission to work with files: it may write, or read, only the file you chose, while that command runs, and when the command fails nothing is written.

Choosing a plugin command opens its form, titled with the command's title and the plugin's name, in the interface's language when the plugin is translated (changing the language loads the plugins again). Its parameters are fields: the required ones under *Parameters*, the others under *More options*, which are sent only when you set them (left alone, or emptied, the command's own default applies). Lengths are typed in the project's units. An empty required field says *Required*. A file field has the path and **Browse…**, which opens the save or open dialog for the file types the plugin names; the plugin may write (or read) that file while the command runs, even without the permission to work with files. An element field has **Pick** (the form hides; click the element in the active view, 2D or 3D; Esc or another tool brings the form back unchanged) and **Selection** (the one selected element); a list of elements starts from the selection and has **Selection** and **Clear**; a point is picked in a plan, snapping as the drawing tools do. Levels, views, types and materials are chosen from lists. **Run** stays disabled until every required field is filled and every value is valid; its tooltip says what is missing. It runs the command as one undo step: an error stays in the form; a result, or what the plugin printed, is shown (**Run Again** goes back to the form with its values); with nothing to show the form closes and the status bar says it is done. **JSON** shows the arguments as JSON, as scripts write them, and back. A command without parameters runs as soon as it is chosen.

**A plugin command running an external program** (such as a simulator; see [External programs](automation.md#external-programs)) does not hold the app: its form steps aside and a dialog titled with the plugin's name shows *Running <program>…*, the time elapsed, and the last line the program wrote. Like the other progress dialogs it blocks the rest of the interface, and shortcuts wait; the project shows what the command did so far. When the program ends the command goes on, and its form shows the result, the error or what the plugin printed as usual (or the status bar says it is done, when the command was run from the palette). **Cancel** (or Esc, or the dialog's close button) stops the program and undoes everything the command did; the form then says it was cancelled. The command is one undo step however long it ran.

The Plugins window has two tabs:

- **Installed**: the plugins of the plugins folder. Pick one to see its version, authors, license, page, commands and any error from loading it. *Turned on* loads it or leaves it out (a plugin turned off runs no code). A plugin that asks to work with files has *Allow it to read and write files*; without it, its commands that import, export or save are refused. A plugin that asks to run external programs has *Allow it to run external programs*, with a warning that they run outside the plugin's limits, with your permissions; without it, its commands that run one are refused. A plugin that asks for network access has *Allow it to access the network*, with the hosts it may reach under it (off until you turn it on); without it, its downloads fail and its catalogs ask for it. Its programs are listed under **External programs**, each with its name, the program chosen (*No program chosen* until you choose one, and why it cannot run when the file is missing or has another name), **Browse…** (the open dialog; the file must have one of the names the plugin gives), *Use …* when a program of that name is found on the system's `PATH` (only offered, never chosen by itself), **Test** (runs the program's version check, at most 10 seconds, and shows the first lines it wrote, or why it did not run), and *Where to get it* when the plugin gives a page. The program chosen is kept per plugin in the plugins folder (`.tools`) and goes when the plugin is removed. *Remove* deletes it from the folder. A plugin with settings shows them under **Settings**, also while it is turned off (a note says they apply once it is turned on): a checkbox, a number or length (in the project's units), a list of choices or a text each; a value that does not fit is shown as invalid. **Save** stores the values that differ from the defaults (a value that does not fit keeps the one stored before) and loads the plugins again so the plugin runs with them; **Reset to defaults** clears them.
- **Available**: the plugins of the [community index](https://github.com/francisreboucas/constructcraft-plugins), read when the tab is first opened (*Refresh* reads it again). *Install* (or *Update to …*) downloads the newest version this build can run, checks it against the index's checksum, and installs it only if it loads; a plugin that asks for files, or to run external programs, gets the permission only when you tick its box first.

Only this tab reaches the network: it reads the index and the archives it lists, over HTTPS, when you ask. *Reload Plugins* (in the window's footer, whatever the tab) loads every plugin again from its files, after you add or edit one by hand; the permissions you gave stay, and it waits while a plugin command runs. Plugins are loaded when the app starts and stay loaded when you open another project.

**Plugin console.** *Plugin Console* (in the Plugins window's footer, or *Manage → Plugins → Plugin Console*) opens a window that stays open while you work: each entry has its time since the app started and its plugin, and tells what a plugin printed, why one did not load (in red), an event handler's error or a handler turned off, or that the plugins loaded again. The combo shows one plugin's entries or all, *Clear* empties it and *Copy* puts what it shows on the clipboard; it keeps the last 2000 entries. The status bar still shows the last line a plugin printed.

**Developing plugins.** *Preferences → File locations → Plugin developer mode* checks the plugins folder and the *Development folder* (a plugin's folder, or a folder of plugins; *Browse…* chooses it) every second and reloads the plugins when a `.lua`, `.toml` or `.svg` file changed, with *Plugins reloaded: a file changed.* in the status bar (not while a plugin command runs: then right after). In developer mode the development folder's plugins load like installed ones, with the permissions given to their id; a plugin found in both loads from the development folder, its row says *Development copy*, and the console notes it. A development copy has no *Remove*, settings or programs in the window: change it in its folder. See [Developing a plugin](automation.md#developing-a-plugin).

## Update notice

ConstructCraft tells you when a newer version is published; it never downloads or installs anything by itself, only when you choose **Update Now**.

- **When**: at startup, at most once a day, in the background (the window never waits for it). *File → Check for Updates* (also in the *About* dialog) checks at once and reports "up to date", the new version, or that it could not check.
- **What is contacted**: one HTTPS request to the GitHub API, `https://api.github.com/repos/francisreboucas/constructcraft/releases/latest`, which returns the latest published release. The request sends the usual connection data (your IP address) and a `ConstructCraft/<version>` user agent; no project data, identifier or usage information. GitHub's privacy statement applies to it.
- **What you see**: when the release is newer than the running version (pre-releases are ignored), a notice appears in the status bar and on the home screen: *Download* opens the release page in your browser, *Skip This Version* hides the notice until a later version comes out, and × hides it until the next check. Any failure (offline, timeout, proxy, rate limit) is silent.
- **Update Now**: where ConstructCraft can replace itself safely, the notice and the check's dialog offer *Update Now*. It downloads the package that fits how this copy was installed and checks its SHA-256 against the release's `SHA256SUMS.txt` (both from the release's own download links on GitHub) before anything changes; a download that does not match is deleted and the installed copy is left as it was.

  | Installed as | Update Now does |
  |---|---|
  | AppImage | Downloads the new AppImage next to the old one, checks it, renames it over the old file and offers *Restart Now* |
  | Windows installer (`.msi`, under Program Files) | Downloads and checks the installer; it runs when ConstructCraft closes (*Install Now* closes it, asking about unsaved changes first; *On Exit* waits), and ConstructCraft opens again when it is done |
  | Windows `.zip` | Downloads and checks the archive, puts the new `constructcraft.exe` and `ccad.exe` in place (the old ones are kept as `.old` and removed at the next start) and offers *Restart Now* |
  | macOS app | Downloads and checks the disk image and opens it: drag ConstructCraft to Applications |
  | `.deb` | Nothing: the dialog shows the `apt` command, with Copy, and *Download* gets the package |
  | `.tar.gz`, builds from source | Nothing: *Download* opens the release page |

  Update Now needs write access to the installed files: an AppImage in a folder you cannot write to fails with a message, and *Download* is the way to update it.
- **Turning it off**: clear *Check for updates automatically* in *Preferences → General*. The environment variable `CONSTRUCTCAD_NO_UPDATE_CHECK=1` turns off every check, automatic or on request (useful for CI, kiosks and offline installations). ConstructCraft remembers the last check time, the skipped version and the setting with its other preferences.

## Autosave and recovery

A minute after a project gets unsaved changes (a new project that was never saved too; *Preferences → Saving* sets another interval or turns autosave off), ConstructCraft writes a copy of it, in the background, to the `recovery` folder of its data folder (`%APPDATA%\ConstructCraft\data` on Windows, `~/Library/Application Support/ConstructCraft` on macOS, `~/.local/share/constructcraft` on Linux). It writes again only after the model changes, and never over your project file. Saving, closing the project or quitting removes the copy.

If ConstructCraft crashes or is killed, the next start shows *Recover Unsaved Work* with the copies left behind: *Restore* opens the chosen project with its unsaved changes (saving it writes to its original file, or asks where for a project that was never saved), *Discard* deletes the copy, and *Cancel* keeps the copies for the next start. A crash in the interface also writes a last copy before the app closes, and every crash is appended to `crash.log` in the data folder; attach it when you report a crash.

## Graphics start-up

ConstructCraft draws with the system's native graphics API (DirectX 12 or Vulkan on Windows, Metal on macOS, Vulkan on Linux) and falls back to OpenGL by itself when that fails, which some older or small integrated GPUs need:

- If the native API reports an error, the same start tries OpenGL. If it crashes before the window appears, ConstructCraft starts again once with OpenGL; if the whole process dies (a driver crash), the next start tries OpenGL first.
- Once OpenGL was needed, it stays first: the choice is kept in the file `gpu-backend` of the data folder. Delete that file (after updating the graphics driver, for example) to try the native API again.
- Every failed start is written to `crash.log` in the data folder. When no API works, a message says so and names that file.
- The environment variable `WGPU_BACKEND` picks the API yourself and turns the fallback off: `gl` for OpenGL, `dx12`, `vulkan` or `metal`, or several separated by commas (on Windows, for example, `set WGPU_BACKEND=gl` in a command prompt before starting `constructcraft.exe`, or as a user environment variable). `WGPU_POWER_PREF=low` prefers the integrated GPU on computers with two.

## Accessibility

The ribbon buttons, tab titles, scroll arrows, palette entries, browser rows, home screen cards, dialog close buttons, property sections and the view cube's home button are drawn by ConstructCraft itself. They report their role (button, selectable item, collapsible header), their name and their state (enabled, selected, expanded) to the operating system's accessibility interface, so screen readers can announce them.

## For developers

### Adding a command to the interface

1. Make the change an engine command first (see *For developers* in the [automation guide](automation.md)).
2. Add a variant to `UiCommand` in `crates/cc_app/src/commands.rs`. Then fill in its `icon`, `label`, `description` (an i18n key `cmd-desc-…` in every `.ftl` file), `shortcut` (if any), `engine` (the engine command's name), `badge`, `unavailable` (a localized reason for each state in which it cannot run), `selected` (for tools) and `run`. Add it to `UiCommand::all`.
3. Place it in a ribbon group with `command_button` (large) or in a family of small buttons with `stacks` (`crates/cc_app/src/ribbon.rs`).

The tooltip, enabling, the palette entry and a two-letter shortcut all follow from the command. Tests check that each engine name exists in the catalog, that shortcuts are unique, and that every command appears in the ribbon with an accessible name.

### Icons

Icons are SVG files in `assets/icons/ui` on a 24-unit grid. They use white strokes (`stroke-width` 1.75, round caps and joins) and soft fills written as `fill="#fff" fill-opacity=".2"`. `icons.rs` splits each icon into two layers by those attributes: the strokes and solid marks form the ink, and the soft fills form the tint. Each layer is rasterized with resvg at the exact pixel size and painted in the theme's colors (`icons::Tones`). Add the new icon to `Icon`, `Icon::ALL` and `Icon::source`. `ICON_SHEET=sheet.png cargo nextest run -p cc_app icon_sheet` writes every icon at several sizes for review.

### Theme

Colors are tokens of `theme::Palette`: `PALETTE` (light) and `DARK`, with a test of their contrast. Paint with `theme::palette(ctx)` so a dark theme can be switched on later.

### Interface tests

`crates/cc_app/src/ui_tests.rs` runs the ribbon and the palette headlessly with [egui_kittest](https://crates.io/crates/egui_kittest). The tests click and type through the accessibility tree, so custom widgets must call `Response::widget_info`. Screenshot references live in `crates/cc_app/tests/snapshots`. They cover each ribbon tab, the narrow and collapsed ribbon, a rich tooltip, the palette, each page of the Preferences window, and an icon gallery in both themes. GPUs render slightly differently, so the screenshot comparisons run on request:

```sh
CC_UI_SNAPSHOTS=1 cargo nextest run -p cc_app snapshots     # compare with the references
UPDATE_SNAPSHOTS=1 cargo nextest run -p cc_app snapshots    # rewrite them after an intended change
```

Review the new images before committing them. On a mismatch, kittest writes `*.new.png` and `*.diff.png` next to the references; Git ignores those files.
